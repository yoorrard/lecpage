### 7.3 앱이 읽는 순서(`app/src/lib/ai-catalog.js`)

1. 같은 출처의 `ai-catalog.json`(학교망에서도 닿고 작음, `_headers`에서 `no-cache`, 서비스 워커는 손대지 않음).
2. OpenRouter 실시간 목록이 2.5초 안에 오면 1을 덮어씀(실시간이 더 새로움). 늦으면 1로 먼저 고르고, 실시간 목록은 그 탭의 다음 호출부터 씀. 파일이 없으면 예전처럼 실시간 목록을 기다림(8초).
3. 둘 다 없으면 이름 규칙(`tierByName`·`verOf`)으로 어림. 값표가 있으면 값표에 없는 모델에도 이름 규칙을 쓰지 않고 '표준'으로 둠.

Gemini 무료 키(처음 만들 때 알게 됨):
- 무료 키로 알게 되면 `geminiFree.paidOnly`(4 Carbon·Argon 등)를 써 보기 전부터 '유료 키 필요'로 잠그고, 추천은 `geminiFree.free` 안에서 고름(고품질 등급까지).

- 한 번 실패한 모델을 기억하는 것(`markBlocked`)은 두 번째 안전망으로 그대로.

| 가져온 글이 코드처럼 쓰임 | id·숫자·날짜·참거짓만 담음. 이름·설명·HTML은 버림. 앱은 이 파일을 `JSON.parse`로만 읽고 화면에 HTML로 넣지 않음 |
| 자동 커밋이 다른 것을 바꿈 | 워크플로는 `ai-catalog.json`만 `git add`. 권한은 `contents: write`·`issues: write`뿐, 액션은 SHA 고정, 체크아웃에 토큰을 남기지 않고 push 단계에서만 씀, 포크에서는 안 돎 |
| 바뀐 파일이 앱을 깨뜨림 | 커밋 전에 `scripts/ai-catalog/test`(앱 규칙으로 새 파일을 읽고 회사마다 추천이 나오는지 포함)를 돌림. 파일이 깨지거나 없어도 앱은 실시간 목록 → 이름 규칙으로 예전처럼 동작 |
| 이슈 도배 | 같은 제목의 열린 이슈가 있으면 댓글로, 문제 목록이 같으면(digest) 댓글도 안 씀. 봇 확인 화면(403)·혼잡은 이슈로 올리지 않음 |

### 7.5 시험

- `node --test "scripts/ai-catalog/test/*.test.mjs"`(루트 `npm test`에 포함): 표본(`test/fixtures`, 실제 응답과 같은 모양의 만든 자료)으로 네트워크 없이 — 각 출처 해석, 검사(깨진 자료·급감 거부), 출처가 끊긴 날, 이름 점검, 추천 어림, CORS·주소 판정, 한 번 돌리기(갱신→바뀐 것 없음→거부), 앱 쪽 읽는 순서(같은 출처 → 실시간 → 이름)·`rankModels`·Gemini 무료 키 잠금, 지금 올라가는 `ai-catalog.json`, 서비스 워커·`_headers`.
