## 2. 바로 공개 품질 점검: 실제 공유용 웹페이지로 충분한가

Vercel(강사 계정에 올리는 길)과 견줌. ✓ 원래 됨 · **고침** · 남김(까닭).

| 항목 | Vercel | 바로 공개 | 결과 |
|---|---|---|---|
| HTTPS | 자동 | workers.dev·내 도메인 모두 자동 | ✓ + **고침**: 내 도메인에 http로 오면 https로 308, 모든 응답에 HSTS |
| 첫 방문 속도 | 전 세계 CDN 캐시 | 파일마다 Worker → Durable Object(한 지역) | **고침**: 런타임 스크립트는 정적 자산(`/rt/<sha>.js`, CDN), 그 밖의 파일은 내 도메인일 때 데이터센터 캐시 10분 |
| 다시 방문 | 해시 붙은 파일은 1년 | 모든 파일 10분 뒤 다시 물어봄 | **고침**: HTML이 부르는 사이트 파일에 `?v=<지문>`을 붙이고 1년 `immutable`. HTML은 `no-cache`+etag(배포 id 포함)라 다시 올리면 바로 바뀜 |
| 압축 | 자동 | Cloudflare가 글자 응답을 자동 압축 | ✓ |
| 휴대폰 | 사이트 나름 | 엔진이 반응형, 호스트 안내 화면도 viewport | ✓ |
| QR·짧은 주소 | 앱이 만듦 | 앱이 만듦(`/s/` + 10자라 원래도 짧음) | ✓ |
| 참여 기능 | 없음(따로 연결) | 같은 서버의 방 | ✓ |
| 공개 기간 | 계속 | 30일, 방문이 있으면 다시 채움(1년까지) | ✓(비용 절감용 설계) |
| 내 도메인 | 사이트마다 | 운영자 도메인 하나 | 남김: 사이트마다 도메인은 인증서·호스트 이름 관리가 유료(Cloudflare for SaaS)라 운영비 0 원칙과 맞지 않음. 앱의 '내 계정에 올리기'로 |
| 검색 노출 | 고를 수 있음 | 늘 `noindex` | 남김: 여러 사람이 한 출처를 쓰는 무료 호스트라 검색 스팸에 쓰이면 호스트 전체가 손해. 검색이 필요한 사이트는 '내 계정에 올리기' |
| 링크 미리보기 카드 | og 태그대로 | `robots.txt`가 모든 봇을 막아 슬랙·X 등은 카드를 못 만듦. `og:url` 없음, `og:image`도 대부분 없음 | **고침**: 미리보기 봇(카카오톡·페이스북·X·슬랙·디스코드·텔레그램·링크드인·왓츠앱)만 `/s/`를 읽게 열고 검색 로봇은 계속 막음. `og:url`을 붙이고, `og:image`가 없으면 첫 화면의 큰 그림(8KB 넘는 png·jpg·webp)을 전체 주소로 |
| 404·오류 화면 | 있음 | 사이트의 404.html, 호스트 안내 화면 | ✓ |
| 보안 머리글 | 기본 | CSP·nosniff·틀 막기 | ✓ |

첫 화면 하나를 여는 데 Worker에 가는 요청(예시 사이트 `sel-story`·`data-lab`, 글꼴은 바깥 CDN):

| | 전 | 뒤 |
|---|---|---|
| 참가자 화면 첫 방문 | 9 | **6**(boot·lecpage·참여 기능 스크립트가 `/rt/`로) |
| 강사 화면 첫 방문 | 9 | **5** |
| 10분 넘어 다시 열기 | 9(304라도 요청) | **1**(HTML 304) |
| 두 번째 사이트를 열 때 | 다시 받음 | `/rt/`는 이미 브라우저에 있음 |

40명 연수 한 번이 2천~1만 2천 요청이던 어림에서 페이지 여는 몫이 3분의 1~9분의 1로 줄어든다. 실시간 방(질문·투표)의 요청은 그대로라, WebSocket이 막힌 학교망의 5초 묻기 방식이 여전히 가장 큰 몫이다.

## 3. 무료 요금제로 안전하게 열기

문제(보안 검토 2차 I3): 하루 Worker 요청 10만 건을 모든 사이트가 나눠 쓰고, 다 쓰면 그날 올라온 사이트까지 멈춘다. 누구나 요청을 6만 건 보내 그날의 새 사이트를 멈출 수 있다.

| 장치 | 동작 | 남는 것 |
|---|---|---|
| 하루 예산 60%에서 새 사이트·새 방만 멈춤(있던 것) | 남은 40%를 방문에 씀 | 60% 넘기기는 여전히 누구나 가능(새 사이트만 멈춤) |
| 요청 줄이기(§2) | 방문 한 번의 요청 수를 줄여 같은 한도로 더 많은 연수 | — |
| 데이터센터 캐시(Cache API, 내 도메인일 때) | 사이트 파일 응답을 10분 둬 Durable Object 요청을 덜 씀(DO에도 하루 요청 한도가 따로 있음) | Worker 요청 수는 줄지 않음. 가린 사이트의 그림·CSS가 캐시에 10분까지 남을 수 있음(HTML은 바로 451) |
| 없는 주소 1분 기억 | 주소 두드리기가 DO를 깨우지 않음 | — |
| 덜 급한 일 미루기 | 예산 85%부터 앱 이용 합계는 Gate를 부르지 않고 버림 | — |
| 알림 웹훅 | 50·60·80·95%, 저장량 80%에서 한 번씩(Slack `text`·Discord `content`) | 알림을 받고 운영자가 움직여야 함 |
| 새 업로드 멈춤 스위치 | 관리 화면·curl로 새 사이트·다시 올리기·새 방을 멈춤(앱은 '내 계정에'로 안내) | — |
| WAF 속도 제한 규칙 1개(운영자가 켬) | 한 IP가 10초에 400건을 넘으면 10초 막음. Worker에 닿기 전이라 요청 수에도 안 듦 | 여러 곳에서 오는 폭주는 못 막음. 내 도메인이 있어야 함 |
| Workers Paid(월 $5) | 하루 한도 없음 | 유일하게 '멈추지 않음'을 보장. 판단 기준은 관리 화면이 계산(§4) |

봇: 정상 검색 로봇은 `robots.txt`를 지키고, 미리보기 봇은 공유된 주소만 연다. Bot Fight Mode는 미리보기 봇과 앱의 API 요청을 막을 수 있어 끄라고 안내했다. 'Block AI bots'는 켜도 된다.

## 4. 관리 화면

```
운영자 브라우저 ──▶ Cloudflare Access(정책: 운영자 이메일 하나, 일회용 번호 또는 2단계 인증 계정)
                     │ 통과하면 Cf-Access-Jwt-Assertion(RS256 JWT)을 붙여 넘김
                     ▼
Worker /admin*  ──▶ ① ACCESS_TEAM_DOMAIN·ACCESS_AUD가 없으면 404
(run_worker_first)  ② JWT 확인: 팀의 공개 열쇠(<팀>/cdn-cgi/access/certs, 1시간 캐시, 모르는 kid면 1분에 한 번 다시)로 서명,
                       iss = 팀 주소, aud ∋ ACCESS_AUD, exp·nbf·iat(1분 여유), email 있음(서비스 토큰 거절), type = app,
                       (선택) ACCESS_EMAILS에 있는 이메일
                    ③ 화면 파일(public/admin/ 세 개만) 또는 /admin/api/… → CSRF 확인 → Gate·Site
```

- 팀 도메인은 `<이름>.cloudflareaccess.com` 모양만 받는다(로컬 시험만 `http://127.0.0.1:<포트>`). 설정 실수로 다른 곳의 열쇠 목록을 믿지 않게.
- 숫자: Worker가 isolate마다 요청 수와 갈래(사이트 파일·API·참여 기능·관리·5xx·429·캐시 적중·막은 요청)를 세어 50건이나 30초마다 Gate에 보낸다. Gate는 하루 한 줄(JSON)에 더해 **보낼 때마다 한 줄만 쓴다**(DO 쓰기 한도 10만 행/일을 아낌). 새 사이트·공개·새 방·신고는 Gate가 그 자리에서 센다. 하루 숫자는 400일.
- 유료 전환 한 줄: 최근 7일 중 하루 예산 50%를 넘은 날이 2일 이상이면 권함. 가장 많은 날 %도 함께.
- 감사 기록: 가리기·풀기·지우기·신고 처리·공지 만들기/고치기/끄기·새 업로드 멈춤/다시 받기. 누가(Access 이메일 또는 'ADMIN_KEY(curl)')·언제·무엇을·대상·내용. 최근 2,000개. 지우는 API는 없다. 운영자 이메일은 Cloudflare 안의 이 기록에만 있고 저장소·로그에는 남기지 않는다(로그에는 거절 까닭 코드만).
- 화면 찍기(로컬, 지난 29일 숫자는 시험용으로 채움): `/tmp/claude-0/-home-user-lecpage/6c566d4e-a9d8-5130-a565-63612608ad41/scratchpad/admin/` 의 `admin-desktop.png`·`admin-mobile.png`·`admin-desktop-dark.png`·`admin-chart-hover.png`·`admin-delete-confirm.png`·`admin-no-access.png`·`teacher-console-notice.png`·`app-notice-desktop.png`·`app-notice-mobile.png`.

## 5. 앱 공지와 익명 이용 합계: 한 것과 까닭

**공지**: 앱이 켜진 뒤 한가할 때(`requestIdleCallback`) 따로 받는 묶음(`after-load` 청크)에서 가져온다. 첫 화면 JS에는 `import()` 한 줄만 늘었다. 바로 공개 서버가 있으면 `GET <서버>/api/notice?for=app`, 없으면 앱 배포의 `notice.json`(운영자가 저장소에서 고침, `no-cache`). 처음 보일 때 그 공지 id를 이 브라우저에 적어 다음에는 띄우지 않는다(고치면 id의 판 번호가 바뀌어 한 번 더 보임). 글자는 Preact 글자 노드로만, 링크는 https만 다시 확인하고 가는 곳의 호스트를 옆에 보인다.

**익명 이용 합계를 넣은 까닭**: 앱은 정적 파일이라 운영자에게는 앱이 얼마나 쓰이는지 알 길이 없고, 바로 공개를 무료로 둘지 월 $5로 올릴지는 '바로 공개로 올리는 비율'이 핵심 숫자다. 서버 요청 수만으로는 앱 쪽 흐름(만들기는 하는데 공개를 안 하는지, 어느 올릴 곳을 고르는지)을 알 수 없다. 그래서 개인정보 최소 원칙 안에서 가장 작은 모양으로 넣었다.

| 원칙 | 지킨 방법 |
|---|---|
| 개인을 알아볼 수 없게 | 보내는 것은 `{ e, k }`(일 이름과 갈래)뿐. 서버는 IP·시각·식별자를 저장하지 않고 하루 숫자에 1을 더함. 앱 열기는 하루 한 번만(날짜 표시는 이 브라우저에만) |
| 필요한 것만 | 7가지: 앱 열기, 만들기(키·챗봇), 공개(바로 공개·Vercel·GitHub·Netlify) |
| 운영비 0 | 바로 공개 서버가 있을 때만(그 서버로). 서버가 없는 앱은 아무것도 보내지 않음 |
| 알리고 끌 수 있게 | 처리방침 9-1·도움말 한 줄·설정 [이용 합계] 끄기, DNT·GPC 존중, 2026-11-20 전에는 보내지 않음(처리방침 변경 7일 전 공지) |

하지 않은 것: 화면별 머문 시간, 오류 내용, 브라우저 종류, 유입 경로, 세션. 필요해 보여도 위 표를 넘는 것은 처리방침을 다시 고친 뒤에.

## 6. 보안 검토(위협 모델)

| 위협 | 경로 | 막은 방법 | 남는 위험·운영자 할 일 |
|---|---|---|---|
| 관리 화면 무단 접근 | `/admin` 직접 열기, 머리글 지어내기 | Access 정책 + Worker의 JWT 서명·iss·aud·만료 확인(시험: 다른 열쇠·만료·다른 AUD·다른 팀·이메일 없음·alg 바꾸기·`none` 모두 403). 설정 없으면 404 | 정책을 'Everyone'처럼 넓게 잡는 실수 → `ACCESS_EMAILS`(비밀)로 한 번 더. 내 도메인을 붙인 뒤 `workers_dev: false`로 workers.dev 주소를 닫으면 Access를 돌아가는 길이 없어짐(토큰이 없으면 어차피 403) |
| 열쇠 혼용 | curl 열쇠로 화면 API, 화면 토큰으로 curl API | 둘을 나눔(시험으로 확인) | `ADMIN_KEY`는 쓰지 않으면 비워 둠 |
| 토큰 탈취 | 쿠키·토큰 재사용 | 토큰은 AUD에 묶이고 세션 길이까지만. Binding cookie·SameSite Strict·HTTP Only 안내 | 운영자 메일 계정 2단계 인증 |
| XSS(관리 화면) | 사이트 제목·신고 내용·공지·감사 기록에 든 HTML | 모든 글 `textContent`, CSP `script-src 'self'`·인라인 없음·Trusted Types, 시험이 `innerHTML` 등을 찾음 | — |
| XSS(공지) | 공지 제목·본문 | 서버는 글자만 저장(보이지 않는 글자·방향 바꿈 글자 뺌), 강사 화면 띠는 서버가 이스케이프(스크립트 없이 `<details>`), 앱은 Preact 글자 | — |
| CSRF | 다른 사이트가 운영자 브라우저로 요청 | 전용 머리글(`x-lecpage-admin`, CORS 안 엶) + 같은 Origin + `Sec-Fetch-Site` + JSON만, Access 쿠키 SameSite Strict, 지울 때 주소 10자 다시 적기 | — |
| 틀 속 클릭 유도 | 관리 화면을 iframe에 | `frame-ancestors 'none'`, `X-Frame-Options: DENY` | — |
| 공지로 피싱 링크 | 운영자 계정이 털리거나 실수 | https만, 계정·포트·IP 주소·보이지 않는 글자·`javascript:` 거절, 링크 옆에 가는 곳 호스트, `rel="noopener noreferrer"`, 기간 90일까지, 감사 기록, (선택) `NOTICE_LINK_HOSTS`로 갈 수 있는 곳 고정 | 공지를 바꾼 기록을 가끔 봄 |
| 통계 조작 | curl로 Origin을 지어내 부풀리기 | 표에 있는 항목만, 허용한 앱 Origin만, 200바이트까지, IP별 1분 20번(메모리만), 항목마다 하루 2만까지, 예산 85%부터 버림 | 정한 상한까지는 부풀릴 수 있음 → 유료 판단은 서버가 센 요청 수로(관리 화면도 그렇게 계산) |

## 8. 못 한 것·확인 필요(공식 문서에 닿지 못함)

- Cache API가 workers.dev 주소에서는 아무 일도 하지 않는다는 것, Durable Object 무료 한도(하루 요청 10만 건 등), WAF 속도 제한 규칙의 무료 요금제 선택지(IP 기준·10초·10초 막기), Zero Trust 무료 요금제 가입 때 결제 수단 확인을 요구하는지 — 모두 기억에 기댄 것이라 배포 전에 대시보드·문서로 확인.
- Access 애플리케이션을 경로(`/admin`)로만 거는 것은 내 도메인에서만 된다(workers.dev의 Access 켜기는 주소 전체를 막아 사이트까지 로그인이 필요해짐). 도메인 없이 관리 화면을 쓰려면 관리 전용 Worker를 하나 더 두고 그 workers.dev 주소 전체를 Access로 막는 길이 있으나 만들지 않았다.
- 카카오톡 미리보기 봇의 이름(`kakaotalk-scrap`)과 `robots.txt`를 지키는지, 링크 미리보기에 그림 크기 조건이 있는지는 실제 공유로 확인하지 못했다.
- 실제 Cloudflare 배포·과금, 실제 Access 로그인, 실제 웹훅 수신.
