# 학교·기관 망에서 lecpage가 막히는 곳과 대비 (2026-11-13)

운영자 요구: "학교에서 하는 연수가 많다. 무료에서도 망 조건 때문에 사이트를 못 만들거나 연수 당일 접속이 막혀 강사가 당황하는 일이 없어야 한다. 말한 것에 한정하지 말고 더 좋은 설계가 있으면 그쪽으로."

이번 구현: 앱 `app/src/lib/{netcheck,venue}.js`·`components/VenueCheck.jsx`·공개·AI 연결 화면, 런타임 `engine/runtime/live/{core,http,supabase,sheets}.js`·`lecpage.js`·`console.js`·`check.js`, 엔진 `src/font-bundle.js`, Node 서버 긴 대기, 바로 공개 서버 `POLL_LONG` 기본값.

## 1. 공개 자료로 확인한 것

검색 2026-11-13. 학교망의 차단 목록·규칙 원문은 공개되지 않아, 구조와 사례로 가능성을 정리하고 설계는 '어느 것이 막혀도 버티게'로 잡았다.

1. **학교 망 구조.** 학교 인터넷은 스쿨넷(학교·교육청을 잇는 전용 회선)이고 업무망과 교육망으로 나뉜다. 행정망과 학생 학습망을 더 나누는 개편이 시범 중이다(바이라인네트워크 2024-10 'NIA 스쿨넷 개편'). 교육부 사이버안전센터 「학교 인터넷 보안 가이드라인」(2023-11 제정)은 업무망·교육망 보안, 유·무선망 혼용 유의점을 다루고, 「교육부 정보보안 기본지침」 제43조(무선랜 보안)에 따라 학교장 책임으로 무선망 보안 대책을 세우게 한다(전북교육청 게시본 목차·발췌. 원문 PDF는 이 세션 망에서 열지 못함).
2. **교사 PC 망분리.** 전북교육청은 업무망과 인터넷망을 나눠 업무용 PC에서는 업무 시스템 접속·문서 작성만, 검색·메일은 인터넷 가상 PC에서 하게 했다(전북일보 2024-06). → 교사가 업무 PC에서 lecpage 앱을 열면 '가상 PC 브라우저'일 수 있고, 그 안에서는 파일 내려받기·클립보드가 막히기도 한다(가상 PC 제품마다 다름, 공개 근거 없음). 공공 업무 PC의 생성형 AI는 2026년부터 N2SF로 허용하는 방향(뉴시스 2026-03)이고, 교육청 생성형 AI 지침은 17곳 중 7곳에 없다(뉴시스 2025-11) → **AI 회사 주소가 막혀 있을 수 있다**(학교별로 다름).
3. **유해 사이트 차단.** 교육부·방통위가 만든 차단 프로그램이 학교 PC에 깔리고(2009~), 스쿨넷 유해 차단은 민간 업체가 5년 단위로 공급한다(보안뉴스 2017 '수산아이앤티 서울교육청 스쿨넷'). 차단 사유가 '유해'보다 '업무와 무관'인 경우가 있어 교육용 사이트도 걸린다(로직 퍼즐 사이트 해제 청원, 서울교육청 '비업무용' 차단 설명, 한국교육신문). → 새 도메인·개발용 도메인(`*.pages.dev`·`*.workers.dev`·`*.vercel.app`)이 분류 없음·평판 낮음으로 걸릴 수 있다.
4. **보안 게이트웨이의 '새 도메인' 범주.** Cloudflare Gateway 같은 제품은 '등록 30일 안 도메인(New Domains)'·'처음 본 지 30일 안(Newly Seen Domains)' 범주를 두고, 주로 막거나 돌리는 정책에 쓴다(Cloudflare 공식 domain categories). 사이트마다 새 하위 도메인을 받는 바로 공개(Pages)는 하위 도메인 단위 판정이면 '처음 본 곳'이 된다. 피싱에 개발 도메인이 많이 쓰인다는 보고는 [hosting-setup-2026-11](hosting-setup-2026-11.md) §5.
5. **스마트기기 MDM.** 서울 '디벗'은 MDM으로 시간 제어·SNS·게임 차단을 하고, 교사에게는 관리 권한이 없으며 업체가 원격 지원한다(서울신문 2024-07, 비즈한국). → 학생 기기에서 열리게 하려면 허용 목록 요청(정보 담당자 → 업체)이 필요하고 며칠 걸린다. **전날 점검이 아니라 '공개하자마자 점검'이 필요한 경우**가 있다.
6. **학생 휴대폰.** 전기통신사업법 제32조의7(2015-04-16 시행)로 청소년 휴대폰에는 유해정보 차단 수단이 깔리고, iOS는 MOIBA '사이버 가디언'이다(법률신문·뉴스). → 학생 대상 연수에서 '휴대폰 데이터로 열기'도 차단 앱에 걸릴 수 있다(교원 연수는 해당 없음).
7. **기업·기관 프록시의 웹소켓.** 프록시가 `Upgrade: websocket`을 떼거나 TLS 검사로 다시 서명하면 웹소켓이 실패하고, 실패가 바로 오지 않고 멈추기도 해서 클라이언트 쪽 제한 시간이 필요하다. 긴 대기 묻기는 보통 HTTPS처럼 보여 통과한다(Socket.IO·Phoenix 사용자 사례 모음). 오래 붙잡은 요청을 끊는 프록시도 있다. → 런타임은 웹소켓 4초 제한·SSE 4초 제한(전부터)과, 긴 대기가 두 번 끊기면 간격 묻기로 내려감(이번).
8. **글꼴·CDN.** 외부 접속이 막힌 망에서 머리의 글꼴 스타일시트가 약 20초 기다린 뒤 실패하고 그동안 화면이 비거나 늦게 뜬다(ABP 지원 게시판, Remy Sharp 'Fonts, Third Parties and Scripts'). 한국 학교에서 구글 글꼴·jsDelivr가 막힌다는 공개 자료는 찾지 못했지만, 막히면 피해(첫 화면 지연)가 커서 기본값으로 막는다(§7).
9. **카카오톡 인앱 브라우저.** Android에서 blob·data 주소 내려받기가 되지 않는다(카카오 개발자 포럼). 참가자가 카톡으로 받은 주소를 열면 '내 기록 내려받기'가 안 될 수 있다(이번 범위 밖, §11).

**찾지 못한 것**: 교육청 필터가 `*.pages.dev`·`*.workers.dev`·`*.vercel.app`·`is.gd`를 어떻게 분류하는지, 학교 무선망의 웹소켓 차단 정책, 교사 PC 보안 프로그램별 동작. 그래서 '한 번 열어 보기'(전날 점검)를 가장 확실한 대비로 두고 앱이 그 일을 쉽게 만든다.

## 3. 설계 원칙

1. **미리 안다**: 만들 때는 쓸 곳만 그때 한 번(요청 1개, 6초 안, 이 탭에 열림 10분·막힘 3분 기억). 공개 뒤에는 연수 장소에서 전날 한 번.
2. **막히면 저절로 다른 길**: 기다리게 하지 않고 바꾼 뒤 한 줄로 알림("이 망에서 Vercel에 닿지 않아 GitHub Pages로 바꿨어요"). 강사가 다시 고르면 그대로 둠.
3. **사이트는 늘 온전**: 참여 기능·짧은 주소·글꼴이 막혀도 교재·실습·프롬프트 복사는 그대로.
4. **강사 화면 한 줄**: 지금 묻기 방식과 할 일, 전날 점검 결과.
5. **과하지 않게**: 확인은 필요할 때만, 비상 키트는 접힌 한 칸.

## 4. 만들 때·공개할 때: 가벼운 확인(`app/src/lib/netcheck.js`)

- 확인은 인증 없는 가벼운 주소 하나. 응답 머리글을 받으면 바로 끊어 본문은 받지 않는다.
  - AI 회사는 키 없이 2xx를 주는 주소(2026-11-14 직접 확인): OpenAI `/healthz`(200, CORS 머리글 없음 → no-cors), Claude `/api/hello`(200, no-cors), Gemini `/$discovery/rest?version=v1beta`(200, 출처를 그대로 CORS로 줌), OpenRouter `/models?limit=1`(200). 예전 `/v1/models`는 키가 없으면 401·403이라 브라우저 콘솔에 빨간 줄이 찍혔다.
  - 올릴 곳(`/v2/user`·`/api/v1/user`)은 키 없이 2xx를 주는 주소가 없어 401·403도 '닿음'으로 본다. `/zen`·`create.php?format=json`은 200.
- **cors로 묻는 까닭**: 진짜 서버는 CORS 머리글을 주므로(2026-11-13 직접 확인: Vercel·Netlify·is.gd `*`, Gemini는 출처를 그대로) 학교 필터가 내미는 차단 화면(머리글 없음)은 '막힘'으로 잡힌다. OpenAI `/healthz`·Claude `/api/hello`는 CORS 머리글이 없어 no-cors로 묻는다(필터 차단 화면은 키를 넣어 실제로 부를 때 오류로 드러남).
- **챗봇 사이트를 묻지 않는 까닭**: `claude.ai`는 `Cross-Origin-Resource-Policy: same-origin`, `gemini.google.com`은 `same-site`를 줘서 다른 출처의 no-cors 요청을 브라우저가 막는다(열려 있어도 '막힘'으로 보임). 막히면 강사가 연 창에서 바로 보이므로 따로 묻지 않는다.
- 쓰는 곳: AI 키 연결 화면(고른 회사), AI로 만들기·다듬기를 누를 때(막혔으면 오류 대신 챗봇 창 길을 바로 엶), 공개하기(고른 곳, 막혔으면 다음 추천 곳), 짧은 주소(아직 없을 때).
- 요청 수: 한 화면에서 많아야 1~2개, 같은 곳은 10분 안에 다시 묻지 않음. 오프라인이 되면 기억을 지움.

## 5. 연수 장소 확인(공개 체크리스트·공개 카드)

- 공개 전(체크리스트 '연수 장소 확인'): 바로 공개를 쓸 때 상태 API(`GET /api/status?date=`) 한 번 → "11월 20일 바로 공개 예약: 연수 4개 · 참가자 180명. 빠듯해요(하루 몫의 52%)" / 꽉 차면 할 일로 펼침("내 계정에 올리면 붐벼도 상관없어요"). 만들 때 서버가 거절하는 것(예약형 수용량)보다 먼저 보인다.
- 공개 뒤(공개 카드 '연수 전날 점검'): 접속 확인 주소·QR·[접속 확인 열기]·[전날 점검 달력에 넣기]·[주소 복사], 짧은 주소가 있으면 "그곳에서 짧은 주소도 열어 보세요".
- **달력 일정(.ics)으로 한 까닭**: 브라우저 알림은 그 시각에 앱 탭이 열려 있어야 하고(서비스 워커·푸시 서버 없음) 권한 창이 먼저 뜬다. .ics는 휴대폰·구글·아웃룩 달력에 들어가 그날 알림이 온다. 일정: 연수 전날 15:00~15:20(한국 시간, UTC로 적음), 10분 전 알림, 설명에 접속 확인·사이트·두 번째 주소와 막혔을 때 할 일. RFC 5545 줄 접기(75바이트, 한글이 잘리지 않게).
- 접속 확인(check.html)은 결과를 **이 기기에만**(`localStorage` `lp-check:<사이트 경로>`) 남기고, 같은 사이트의 강사 화면이 맨 위에 "접속 확인 11. 12. 15:10 · 연수는 할 수 있어요 · 참여 기능 천천히 묻기"로 보여 준다. 서버로 보내지 않는다.
- MDM 학교(§1-5)는 허용 요청에 며칠 걸리므로 체크리스트 문구가 "공개한 뒤 연수 전날"이 아니라 공개 카드에서 바로 QR을 보여 준다(공개 직후에도 열 수 있음).

## 6. 연수 당일 런타임

| 백엔드 | 실시간 | 막히면 | 이번에 바뀐 것 |
|---|---|---|---|
| local(리허설) | 한 브라우저 | 해당 없음 | 강사 화면에 '리허설 · 이 브라우저 안에서만' 할 일 |
| http(바로 공개 방·Cloudflare·Node 서버) | 웹소켓 → SSE | 묻기 | **긴 대기**: `snapshot?since=&wait=20`(제한 시간 30초). 결과는 core의 동기화 차례를 붙잡지 않는 `snapshot` 사건으로 합침(강사 키 확인·쓰기가 20초 기다리지 않음). 바로 답하는 서버(예전 Cloudflare 백엔드)는 빈 답 두 번 뒤 간격 묻기로. 긴 대기가 두 번 끊기면(프록시) 간격 묻기로. 서버 권고 `X-Lec-Poll-Ms`를 쉬는 틈의 아래 한도로. 숨긴 화면은 긴 대기를 하지 않고 1분(강사 화면 30초), 다시 보이면 바로. 실시간 다시 시도 3→6→12→30분, 숨긴 동안 안 함. **Node 서버도 긴 대기를 지원**(반응 이모지는 깨우지 않음) |
| supabase | Realtime 방송 | 묻기 | 간격 규칙을 core `pollDelay` 한 곳으로(숨김 1분, 바뀐 것 없으면 1.5·2·3배, 20초까지). **라이브러리(jsDelivr)가 막히면 같은 RPC·Storage를 REST로**(실시간만 빠짐) |
| sheets(Apps Script) | 없음(늘 묻기) | — | 같은 `pollDelay` |

- **참여 기능 서버가 아예 안 될 때**(참가자 화면): 처음부터 못 이었거나 20초 넘게 끊기면 질문·보드·투표·설문 칸 위에 한 줄 "참여 기능 서버에 지금 닿지 않아요. 교재·실습·프롬프트는 그대로 쓸 수 있어요. 질문은 손을 들어 해 주세요." 처음 참여하려 하면 참여 창을 띄우지 않고 같은 말을 알림으로. 이미 참여했으면 쓴 글은 보관했다가 연결되면 보냄(전부터). 도움 요청은 "연결되면 보내요. 급하면 손을 들어 알려 주세요." core가 차츰 길게(2초~1분) 다시 이어 보고, 이어지면 한 줄을 거두고 참여 칸을 채운다.
- **강사 화면 맨 위 한 줄**('묻기 방식'): 연결됨 · 바로 받음(웹소켓) / 긴 대기 묻기 · 바뀌면 바로, 없으면 20초마다 / 7초마다 묻기 / 연결이 끊겼어요. 할 일: 학교망이면 "그대로 써도 돼요", 붐비는 날이면 "서버가 붐벼 10초 간격으로 늘렸어요", 끊기면 "참가자 화면의 교재·실습·프롬프트는 그대로 열려요. 질문은 구두로 받고, 설문은 QR로 다른 설문지를 띄워도 돼요." 그 아래 접속 확인 결과(§5) 또는 "연수 장소에서 접속 확인을 아직 하지 않았어요 [접속 확인 열기]".
- 발표 화면: "연결됨(천천히 묻는 중)" / "연결이 끊겼어요 · 다시 잇는 중".

## 7. 글꼴·외부 스크립트

**결정: 글꼴 함께 담기를 앱의 기본값으로**(CLI는 `--bundle-fonts` 그대로).

| 올릴 곳 | 기본 | 까닭 |
|---|---|---|
| 바로 공개(Pages 보기) | 담음 | 정적 요청이 무료·무제한, 사이트 크기 한도 40MB |
| 바로 공개(Worker 보기) | 담지 않음 | 글꼴 조각 요청도 Worker 하루 한도(10만)에 듦 |
| Vercel·Netlify·Cloudflare·ZIP | 담음 | 대역폭이 넉넉, ZIP은 USB(오프라인)에서도 글꼴이 보여야 함 |
| GitHub Pages | 그림·파일이 40개를 넘지 않을 때만 | 파일마다 하나씩 올리고 40개를 넘으면 0.8초씩 쉼(분당 80회 제한) |

- 담는 양을 줄임(`engine/src/font-bundle.js`): ① `src`에 woff2가 있으면 woff2(+`local()`)만(요즘 브라우저는 모두 읽음) ② 사이트 CSS가 쓰는 굵기(`font-weight`·`--…weight` 변수·`font` 줄임 속성 + 400·700)로 **브라우저가 고를 굵기만**(CSS 글꼴 고르기 규칙), 가변 굵기는 그대로 ③ 쓰인 글자가 든 `unicode-range` 조각만(전부터). 예시: data-lab(Spoqa Han Sans Neo 5굵기 × woff2·woff·ttf) 17파일 4,880KB → 5파일 835KB, sel-story(구글 조각) 38파일 1,369KB(그대로, 모두 쓰는 굵기).
- **담지 않은 사이트도 첫 화면이 멈추지 않게**(모든 빌드, `font-bundle.js` `deferFontLinks` + `runtime/boot.js`): 바깥 글꼴 스타일시트를 `media="print" data-lp-font`로 받아 두고 다 받으면 boot.js가 `all`로 바꾼다. 측정(Playwright, 글꼴 주소 응답 없이 버림, sel-story, 휴대폰 화면): **전 8초 뒤에도 첫 화면 없음(하얀 화면) → 후 첫 화면 0.34초**(기본 글꼴, 글꼴이 오면 바뀜). 담은 사이트도 0.34초. 스크립트가 꺼진 브라우저는 기본 글꼴 그대로.
- 참가자가 받는 양은 담아도 거의 같다: `unicode-range`를 그대로 두므로 브라우저는 화면에 필요한 조각만 받는다. 늘어나는 것은 올리는 크기와 시간.
- 앱(브라우저)에서는 글꼴 요청마다 8초 제한, 하나라도 못 받으면 원래대로(반쯤 담긴 사이트를 만들지 않음)이고 공개 카드에 "글꼴 서버에 닿지 않아 글꼴을 사이트에 담지 못했어요. 연수 장소에서 글꼴이 늦게 뜨거나 바뀌어 보일 수 있어요."
- **외부 스크립트**: 참여 기능 SDK는 Supabase만 바깥(jsDelivr, SRI 고정)에서 받는다. 10초 안에 못 받으면 REST 클라이언트(`lite`: rpc·서명 주소·올리기·지우기, supabase-js와 같은 머리글)로 묻기. 그 밖의 바깥 스크립트(효과 라이브러리)는 움직임 담당 범위라 이번에 손대지 않음(효과가 꺼질 뿐 사이트는 동작).

## 8. 당일 비상 키트(공개 카드 '혹시 안 열리면', 강사용 파일)

접힌 한 칸에 꼭 필요한 것만:
1. **두 번째 주소**: 바로 공개면 서버가 준 `/s/<id>/`(위에 늘 보임). 아니면 사이트 ZIP을 다른 곳(예: Cloudflare 끌어 놓기)에 한 번 더 올리고 주소를 적어 둠(`deploy.second`).
2. **휴대폰 데이터**: 참가자는 Wi-Fi를 끄고 QR, 강사 PC는 핫스팟.
3. **USB**: [사이트 ZIP 받기] → 강사 PC에서 index.html(글꼴까지 담겨 오프라인에서도 같은 모양).
4. **인쇄본**: [실습·프롬프트 인쇄본](일정·실습 단계·프롬프트 원문, A4 인쇄용 HTML). 교재는 원본 파일을 인쇄.
5. [안내 한 장 받기]: 위 내용과 사이트·두 번째 주소·접속 확인 QR이 든 A4 한 장(HTML, 인쇄하거나 휴대폰에 저장). 강사용 파일(ZIP)에도 `혹시안열리면.html`·`실습프롬프트모음.html`로 들어감.

## 9. 묻기 요청 수 전후

측정: `count-polls.mjs`(작업 폴더): Node 서버 + 실제 브라우저 5명, 웹소켓·SSE를 막음(학교망), 40초마다 질문 하나, 4분. 전 = 이번 전 런타임(a875e57), 후 = 이번 런타임(긴 대기를 지원하는 서버).

| 참가자 한 명 | 전 | 후 |
|---|---:|---:|
| snapshot 묻기(1분) | 11.3 | 3.25(그중 긴 대기 12/13) |
| 처음 연결·웹소켓·SSE 시도 포함(4분 평균, 1분) | 12.5 | 4.5 |
| 숨긴 화면(30초 뒤 숨김, 4분 평균) | — | 2.25(숨긴 뒤 1분 1회) |
| 2시간으로 늘리면(처음 연결 5 + 실시간 다시 시도: 전 약 40·후 약 12) | 약 1,400 | 약 410 |

- **50명 연수 2시간(강사·발표 화면 2자리 더해 52자리) 묻기 요청: 약 7.3만 → 약 2.1만(−71%)**. 4분 그대로 늘린 값(전 78,250 · 후 28,080)은 처음 연결 몫을 120분 내내 더한 위쪽 한계.
- 조용할 때(글 없음)는 긴 대기 1분 2.4(전 10초 묻기 6), 글이 쉼 없이 오면 쉬는 틈(5초)마다라 1분 12까지(전과 같음). 질문이 몰리는 몇 분은 전과 비슷하고 나머지 시간이 줄어든다.
- 서버 권고가 10초면 쉬는 틈이 10초가 되어 1분 2(조용)~6(바쁨).
- 전 런타임은 40초마다 글이 오면 빈 묻기가 6번 이어지지 않아(30초) 10초로 늘지 못하고 5초를 지켰다. 예전 어림 '1분 5'(capacity.js `pollPerMin`)보다 실제가 높았다는 뜻이고, `POLL_LONG=off`일 때만 쓰인다.
- 결과 원본: 작업 폴더 `count-polls.json`(사람별 묻기·긴 대기·웹소켓·SSE 시도 수).

## 10. 바로 공개 서버 `POLL_LONG` 기본값

**결정: 기본 on**(끄려면 `POLL_LONG=off`). 근거:
- 이번 런타임이 긴 대기를 쓰고, 서버가 붙잡지 않으면 스스로 간격 묻기로 내려가 안전하다.
- 런타임은 서버에 올릴 때 서버가 내보내는 사본과 대조한다(`runtime_mismatch`). **서버를 다시 배포하면** 그 뒤에 만들거나 다시 올린 사이트는 모두 긴 대기 런타임이다. 이미 올린 사이트(Pages 보기)는 다시 올릴 때까지 예전 런타임이지만, 그 연수의 예약 어림은 만들 때 이미 적어 둔 값이라 바뀌지 않는다.
- 측정(§9)이 1분 3.4라 어림(`capacity.js` `pollPerMinLong`)을 2.4 → 3.4로 올렸다(설정값 하나). 학교망 40명 2시간: 전 런타임 25,830(무료 하루 3~4회·예약 2개) → 17,770(하루 5~6회·예약 3개). 질문이 몰리는 날은 더 들 수 있지만, 예약은 하루 몫의 70%까지만 받고 60%에서 새 일을 멈추며, 서버가 붐비면 `X-Lec-Poll-Ms`로 10·20초를 권하고 런타임이 이제 따르므로 차이를 흡수한다.
- 반응(이모지)이 올 때도 방이 대기 중인 묻기를 깨운다(`hosting/src/room.js` `broadcast`). 반응은 snapshot에 들지 않으므로 깨울 필요가 없다 → §11 남은 일(Node 서버는 이번에 반응을 빼고 깨움).

## 11. 남은 일

1. 바로 공개 서버: 반응(이모지)으로 긴 대기를 깨우지 않게(`room.js`, 서버 코드라 이번에 손대지 않음). `/api/notice`·`/api/status`를 Pages 사이트 출처에도 열면 강사 화면이 서버 공지·그날 몫을 직접 보여 줄 수 있음([hosting-setup](hosting-setup-2026-11.md) §7-5).
2. 실제 학교망에서 확인: 교육청 필터의 `*.pages.dev`·`is.gd` 분류, 긴 대기 30초 요청을 끊는 프록시가 있는지(있으면 런타임이 간격 묻기로 내려감), 가상 PC(망분리) 브라우저에서 내려받기·클립보드.
3. 카카오톡 인앱 브라우저(Android)에서 '내 기록 내려받기'(blob)가 안 되는 문제: 클립보드 복사로 대신하거나 외부 브라우저 안내.
4. 학생 대상(만 14세 미만) 연수: 휴대폰 차단 앱(§1-6)에 걸리는지 실기기 확인.
5. 효과 라이브러리(외부 스크립트) 차단 시 동작은 움직임 담당과 함께 점검.
