# 앱 첫 화면(랜딩) 고도화 — 2026-11

> 결론: 첫 화면을 **교재 한 장이 연수 사이트가 되고, 참가자 휴대폰에 닿고, 연수 뒤까지 이어지는 이야기**로 다시 짰습니다. 그림은 모두 엔진이 실제로 만든 예시 사이트·실제 디자인·실제 컨셉이고, 움직임은 장면마다 하나입니다. 첫 화면이 엔진 전체를 받지 않게 바꿔 첫 JS가 129KB → 25KB(gzip)로 줄었습니다.

코드: `app/src/pages/Home.jsx`, `app/src/landing/*`, `app/src/styles/landing.css`, 그림 `app/src/landing/shots/`(다시 찍기 `node app/scripts/landing-shots.mjs`), 비교 수치 `app/src/data/benchmark.json`.

## 3. 기법과 이유

- **붙박이 스크롤텔링**: 글(단계 넷)은 제자리, 그림 틀만 `position: sticky`. 지금 단계는 IntersectionObserver가 화면 가운데 띠(휴대폰은 그림 아래 띠)를 지나는 단계로 정함. 단계 사이는 시간 기반 전환(transform·opacity·clip-path)이라 스크롤을 멈춰도 그림이 어중간하게 남지 않음.
- **접히는 모서리**: 로고의 접힌 모서리를 첫 화면의 움직임으로. 값 하나(`--ld-k`, `@property`로 부드럽게)로 표지는 clip-path, 날개는 transform(scale)만 바꿔 자리 밀림이 없음.
- **글자 단위 등장·SVG 선 그리기·View Transitions**: 각각 한 장면에서만(컨셉 한 줄, 연수 전·중·뒤, 디자인 고르기).
- **그레인·점 무늬**: 첫 화면 바탕에 아주 옅게, 그림 쪽에서만(글 밑에는 깔지 않음).
- **화면 밖에서는 멈춤**: 장면마다 IntersectionObserver로 `is-on`일 때만 애니메이션. 저절로 넘기기는 보일 때·손대지 않을 때만.
- **첫 화면 성능**: 첫 화면은 엔진을 받지 않음(디자인·효과 수는 빌드 때 계산하는 `virtual:lp-facts`). 첫 화면을 먼저 그리고 아래 구간은 다음 틈에. 넓은 화면 첫 그림은 760px로 줄여 미리 받음. 그림은 `src` 아래에 두어 이름에 해시가 붙고 서비스 워커가 오래 둠.
- **밀림 없음**: 제목은 두 줄 고정(어느 한글 글꼴에서도 들어가는 크기), 소개 글은 줄 자리 확보, 날개는 transform.
- **새 의존성 없음**: Preact·CSS만. QR은 앱에 있던 `qrcode-generator`를 그 구간에 가까워질 때 받음.

하지 않은 것: 구간마다 떠오르는 등장 효과, 카드 기울기, 빛 번짐 배경, 옆 색띠, 큰 숫자 카운터, WebGL, 자이로(iOS는 권한 창이 떠 조작이 늘어남). 앞의 넷은 우리 [디자인 규칙](../../skills/lecpage/references/design-quality.md)의 'AI 티' 목록이라 첫 화면에도 같은 기준을 썼습니다.

## 5. 비교 수치(benchmark.json)

'AI에게 그냥 맡길 때와 다른 점' 아래 '재어 본 값'은 `app/src/data/benchmark.json`을 읽어 그립니다. 파일이 없거나 `items`가 비었거나 제대로 된 항목이 하나도 없으면 구간 전체가 나오지 않습니다. 두 값을 나란히 놓는 조용한 막대와 표(항목마다 자기 단위의 척도, 큰 숫자 카운터 없음)입니다.

```json
{
  "version": 1,
  "baseline": "AI에게 그냥 맡길 때",
  "items": [
    {
      "id": "tokens",
      "name": "쓴 토큰",
      "unit": "토큰",
      "better": "lower",
      "baseline": 182000,
      "lecpage": 15300,
      "digits": 0,
      "measured": "2026-11-20",
      "conditions": "교재 PDF 24쪽, 같은 요청 문장, 같은 모델",
      "method": "docs/research/benchmark-2026-11.md#tokens",
      "note": ""
    }
  ]
}
```

| 칸 | 꼭 | 뜻 |
|---|---|---|
| `name` | ○ | 항목 이름(예: 쓴 토큰·AI 비용·걸린 시간·오간 횟수·한 곳 고치기 비용·접근성 위반 수·교재 반영률) |
| `baseline`, `lecpage` | ○ | 두 값(0 이상 숫자). 막대는 둘 중 큰 값을 끝으로 |
| `measured` | ○ | 잰 날짜 `YYYY-MM-DD` |
| `unit` | | 단위(`%`는 붙여 씀, 나머지는 한 칸 띄움) |
| `better` | | `lower`(낮을수록 좋음) · `higher`(높을수록 좋음) |
| `digits` | | 소수 자릿수(없으면 값 크기에 맞춰) |
| `conditions` | | 조건 한 줄 |
| `method` | | 재는 방법 링크: 저장소 경로(GitHub main으로 이어짐) 또는 https 주소 |
| `note` | | 덧붙임 한 줄 |
| `baseline`(맨 위) | | 비교 대상 이름. 기본 "AI에게 그냥 맡길 때"(특정 제품 이름을 쓰지 않음) |

막대 색: 'AI에게 그냥 맡길 때'는 회색(맥락), lecpage는 강조색. 밝게 #8A847E·#5541C4, 어둡게 #8F8983·#9283EC(dataviz 검사: 대비 3:1 이상, 색약 구분 통과. 회색은 일부러 무채색). 값은 늘 글자로도 있고 범례가 있어 색만으로 구분하지 않습니다.
