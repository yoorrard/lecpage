## 2. 호스팅 사실 (2026-11-09 공식 문서 확인)
- Cloudflare Pages 문서 첫머리: "새 프로젝트는 Workers로 시작". 종료 일정은 없음. https://developers.cloudflare.com/pages/
- Workers 정적 자산 요청은 무료·무제한이며 하루 10만 요청 한도에 들어가지 않음. 예외는 Workers Caching(켜면 과금·집계)과 `run_worker_first` 경로(한도 뒤 429). https://developers.cloudflare.com/workers/platform/pricing/ · https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/
- Workers Builds: 루트 디렉터리의 Wrangler 설정을 읽고, 대시보드 이름 = `name` 필수. 무료 월 3,000빌드분·동시 1개·20분. https://developers.cloudflare.com/workers/ci-cd/builds/
- Workers 내 도메인은 도메인이 Cloudflare 영역이어야 함(Pages는 하위 도메인 CNAME 가능). https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/
- Cloudflare Registrar는 `.kr`을 팔지 않음. `.com` $11.17/갱신 $11.17(가격은 2차 출처). https://www.cloudflare.com/tld-policies/
- lecpage.com·.net·.app·.dev·.page·.io·.kr·.co.kr, lec.page 모두 RDAP 404(미등록, 2026-11-09).
- Firebase Spark 호스팅 전송은 **월 10GB**, 넘으면 다음 달 1일까지 비활성. https://firebase.google.com/docs/hosting/usage-quotas-pricing
- Netlify Drop: 계정 없이 올리되 claim 전 비밀번호 잠금, 1시간 안에 claim, 익명은 IP당 3개. Netlify Free는 하드 한도(모든 프로젝트 정지). https://www.netlify.com/blog/thirteen-years-of-netlify-drop
- Vercel Drop(2026-06): 계정 없이 임시 배포, 파일당 100MB·1회 1GB. https://vercel.com/docs/drop
- Deno Deploy는 2026-10-09 Cloudflare 합류 뒤 약 6개월 운영 후 종료 예정. https://deno.com/blog/cloudflare
- Cloudflare Quick Tunnel: 계정 없음, 동시 요청 200, SSE 안 됨. 문서 주소 이동. https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
- Deploy to Cloudflare 버튼: 하위 폴더를 사용자 GitHub에 복사하고 Durable Objects·비밀값 입력·Workers Builds까지 설정. https://developers.cloudflare.com/workers/platform/deploy-buttons/
- 한국 통신사 일부에서 Cloudflare 무료 요청이 해외 PoP로 간다는 2026 커뮤니티 보고(공식 확인 없음 ⚠️). 앱은 PWA라 첫 방문만 영향. `colo=`로 측정.
- 그대로 맞음: GitHub Pages(1GB, 월 100GB 권고, 헤더 불가, 상업 SaaS 금지), Workers·DO 무료 한도, Supabase·Apps Script 한도, Netlify 크레딧 단가. 자세히: [hosting.md](hosting.md).

### 5.1 발견 목록

| ID | 심각도 | 발견 | 상태 |
|---|---|---|---|
| H1 | 높음 | AI 출력·가져온 프로젝트가 `live.url`·`live.code`·`meta.siteUrl`을 정함 → 관리자 키·개인정보 유출, QR이 피싱으로 | **처리함**: AI 답·가져온 파일의 실시간 주소·키·코드와 QR 대상(siteUrl 등)을 버리고, 강사가 앱에서 연결·확인한 값만 씀(`app/src/lib/blueprint.js` applyInfo·sanitizeImported). 연결은 [연결 확인]을 통과해야 켜짐 |

| L2 | 낮음 | 연수 코드 예측 가능 + 존재 여부가 드러남 | **처리함**: 앱·초안이 무작위 10자 코드(`randomCode`, 약 50비트)를 만듦. 설계도에 코드가 없을 때만 예전 방식을 예비로 씀 |
| L3 | 낮음 | `showEmail:false`여도 privacy.html에 메일, 설계도 공개, 답의 `by` 노출 | **처리함**: privacy.html이 showEmail을 지킴, 공개 답·진행·도움에서 `by` 숨김(`mine` 표시), 설계도는 사이트에 올리지 않음 |
| L4 | 낮음 | GitHub 배포가 기존 저장소를 통째로 덮어씀, PAT 권한이 넓음 | **처리함**: lecpage가 만든 저장소(`.lecpage-site` 표지)가 아니면 덮어쓰기 전에 확인을 받음. 기본 저장소 이름은 영문 `lecpage-날짜-xxx` |
| L5 | 낮음 | AI 키가 sessionStorage에 남음("탭 메모리" 안내와 다름) | **처리함**: 키는 탭 메모리(Map)에만, 기억하기를 고를 때만 암호화해 저장 |
| L6 | 낮음 | 서비스 워커가 모든 화면 응답을 기한 없이 캐시 | **처리함**: 정상·같은 출처 응답만, 주소에 ?가 있는 페이지는 저장 안 함, 오래된 자산 정리(최대 160개) |
| L7 | 낮음 | node-server 기본값(평문 http, 키를 로그에 출력, root 컨테이너, 태그 고정) | **처리함**: Docker `USER node`, compose 기본 127.0.0.1, 생성 키는 0600 파일, 파일 이름 디코딩 오류 처리 |
| L8 | 낮음 | CLI `serve`가 옆 폴더로 빠져나감, 잘못된 `%`에 멈춤 | **처리함**: `path.relative`로 확인, 잘못된 % 는 400, 기본은 127.0.0.1에서만(`--host`로 바꿈) |
| L9 | 낮음 | SVG·HTML 자료가 사이트 출처에서 열릴 수 있음 | 일부 이번 판에서 처리 예정(H2의 자료 허용 목록이 SVG·HTML을 뺌). **교재 해석의 SVG 처리 정리는 미룸** — 사이트로 나가는 길이 막혀 위험이 낮음 |
| L10 | 낮음 | Supabase가 클라이언트의 파일 형식을 믿음 | **일부 처리**: 크기·형식 목록 검사. 내용(매직 바이트) 검사는 SQL로 불가 |
| L11 | 낮음 | Apps Script가 아무 연수 코드나 받음 | **처리함**: `setup()`이 연수 코드를 고정, 다른 코드 거절 |
| L12 | 낮음 | Supabase RPC 제한 없음, 행 잠금 경합 | **처리함**: 잠금 시도(advisory lock)·시간 확인으로 가벼운 보호 |
| L13 | 낮음 | CI·공급망: 액션 SHA 미고정, 권한 범위, vite 취약점, 백엔드 lockfile 없음 | **처리함**: 액션 커밋 SHA 고정, 배포 권한은 deploy 작업에만, checkout `persist-credentials: false`, vite 6.4.6, Cloudflare 백엔드 lockfile, Dependabot(7일 대기)·CodeQL·SECURITY.md |
| L14 | 낮음 | 교재 해석이 메인 스레드에서 돌아 큰 XML에 탭이 멈춤 | **미룸** — 강사 본인 기기·본인 파일에서만 생기는 멈춤이라 영향이 작음. 교재 해석을 Web Worker로 옮길 때 함께 |

참고 항목(상태 미지정, 통합 담당이 정함)
- 암호 모드는 호스트 기능이 아니라 **내용 암호화**로 지킵니다. `robots.txt`·noindex는 접근 제어가 아닙니다(문서에 명시함).
- 앱 아래쪽 "교재와 키는 이 브라우저 밖으로 나가지 않아요"는 BYOK AI·GitHub 배포를 쓰면 사실이 아님 → 문구 수정 필요.
- 익명 질문도 서버에는 `by`가 남음 → 개인정보 안내에 밝히기.
- 참가자가 별명을 "강사"로 바꿔 강사를 흉내 낼 수 있음.

### 5.2 이미 잘된 점(확인함)
렌더러는 모두 이스케이프하고 `safeUrl`은 `javascript:`·`data:` 등을 막음(퍼즈 20만 건 통과). SQL은 매개변수화, node-server에 SSRF 없음, 업로드는 매직 바이트로 형식 확인, 해시는 고정 시간 비교, 쿠키가 없어 CSRF 없음, CSV 수식 주입 막음. 미리보기 iframe은 `allow-same-origin` 없이 격리, OpenRouter는 PKCE, 배포 토큰은 화면 상태에만. git 기록에 비밀값 없음.

### 5.3 공용 중계를 다시 검토할 때의 최소 통제
지금은 하지 않습니다. 다시 검토한다면 아래를 **모두** 갖춘 뒤에만 엽니다.
- 방 만들기: Turnstile 서버 검증 + IP당 생성 제한 + 하루 전체 상한(차단기). `OPEN_INIT` 금지.
- 방 ID: 서버가 만든 80비트 이상(HMAC 서명). 모르는 ID는 Durable Object를 만들기 전에 거절. 클라이언트가 고른 코드 금지.
- 무료 한도 보호: IP별 읽기 제한, 웹소켓 하이버네이션만(SSE 끄기), 방·IP별 연결 상한, 꺼짐 스위치(`RELAY_ENABLED=false`), 한도 70% 알림.
- 내용: 글자만(파일 올리기·외부 URL 없음), 방별 인원·문서·용량 상한, 서버 강제 사전 검토, 운영자 삭제 창구, 정보통신망법 임시조치 절차.
- 개인정보: 별명만(이름·학교 거절), 마지막 쓰기 N일 뒤 + 생성 30일 뒤 무조건 삭제, 처리방침에 운영자·Cloudflare 국외 이전 명시, 로그에 헤더·본문·전체 방 ID 남기지 않기.
- 관리자 키: 서버가 128비트로 만들어 한 번만 보여 줌, 헤더로만 전송, 실패 횟수 제한(웹소켓 3번이면 끊기).
- 법률 검토.

### 5.4 저장소·운영 점검
- SECURITY.md + Private vulnerability reporting, Dependabot, 비밀값 검사, 브랜치 보호, 2단계 인증 → 운영자 점검표([operations.md](../operations.md) §6).
- 액션 SHA 고정, 배포 권한을 deploy 작업으로만, vite 업데이트, 백엔드 lockfile → L13(이번 판에서 처리 예정).
- CodeQL·OpenSSF Scorecard·harden-runner, 보안 회귀 테스트 묶음, `runtime/vendor/qrcode.js` 출처·해시 기록 → 위 항목들을 고치는 판에서 함께. 따로 남은 것은 **미룸**(이유: 1인 운영, 먼저 실제 취약점부터).
