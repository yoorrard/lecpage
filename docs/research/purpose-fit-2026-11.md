## 4. AI 경로에서 드러난 프롬프트의 빈틈

프롬프트(`engine/src/prompt/bridge.js`)가 시킨 대로만 답했을 때 생긴 일이에요.

1. **표를 담을 칸이 없어요.** 기준표·역할표·적용 일정표를 `text` 칸에 마크다운 표로 썼더니 화면에 `| 구분 | 기준 |`, `|---|---|`가 그대로 보여요(`runs/m2/ai/dist`, `scripts/site-probe.cjs`로 확인: criteria 칸 날것 4곳, roles 3곳). 인용(`>`)도 그대로예요. 프롬프트는 `text (글): md`라고만 하고 무엇이 그려지는지 말하지 않아요.
2. **사례·토론 질문·절차를 담을 칸이 정해져 있지 않아요.** 저는 절차를 `steps5`, 세 기둥을 `steps5`, 사례·질문을 `text`, 성찰을 `reflection`에 넣었어요. 다른 모델은 다르게 넣을 거예요(같은 요청을 두 번 돌리면 구조가 달라질 곳).
3. **온라인 주소**: 프롬프트는 `meta.joinUrl`에 회의 주소를 쓰라고 하지만 앱은 그 값을 버려요(`intake.js` `applyInfo`의 `UNTRUSTED_META`). m5의 유튜브 중계 주소가 첫 화면 버튼에서 사라졌어요. 프롬프트에서 `joinUrl`을 빼고 "강사가 입력" 값으로만 받는다고 적어야 해요.
4. **"강사가 준 값만"의 범위**: 규칙 9는 문의처·다시 보기·이수 일정을 강사가 준 값만 쓰라고 해요. 그런데 교재에 적힌 문의처·이수 처리 일정(m4 "1. 29.(금) 나이스 등록")은 교재 것이라 써도 되는지 알 수 없어요. 저는 초안에 이미 있는 문의처는 두고, 이수 처리 일정은 뺐어요 → 사이트에서 빠짐.
5. **교재 보기**: `deck: slides[{page,title,text,tools[]}]`를 AI가 다시 써야 해요. 저는 쪽 번호와 제목만 썼고, 그 결과 쪽별 글(검색용)과 쪽별 도구가 사라졌어요. 초안은 앞 3쪽만 보내므로(`slimDraft`) 모델은 나머지 쪽을 지어내거나 비워요. 교재 보기는 AI에게 맡기지 말고 엔진이 채워야 해요.
6. **숨긴 쪽·발표자 노트**: 글에는 `[숨김]`, `> 노트:`로 들어가지만 어떻게 쓰라는 말이 없어요. 노트의 "막히면: …"은 실습 `note`에 썼고, 진행 메모("10분이 지나면 다음 단계로")는 뺐어요. 모델마다 다를 곳이에요.
7. **초안이 프롬프트의 절반**: m1 프롬프트 19,881자 가운데 초안 JSON이 9,895자예요. 그 안에 `_draft`(테마 색 12개·할 일), `live.code`, `privacy`, `deploy`, 기본 설문 문항 5개, `sourceFonts`가 그대로 들어가요. 교재 글(3,912자)과 겹치는 내용이에요.
8. **프리셋 설명이 공식 연수를 한 곳으로 몰아요**: "설명회·직무연수에"라는 말이 `official-brief`에만 있어서 m4·m5가 같은 디자인이 됐어요.
9. 검증(`validate`)은 다섯 답 모두 오류 0·주의 0으로 통과시켰어요. 날것 마크다운, 쪽 글이 빈 교재 보기, 버려지는 `joinUrl`은 경고가 없어요.

## 5. 쉬움 (앱)

앱을 빌드해 띄우고(`vite preview`, 포트 4184) 기본 경로를 Playwright로 따라가며 화면마다 글자 수·버튼·입력을 셌어요(`scripts/app-walk.cjs`). 문구는 다른 작업자가 고치는 중이라 흐름과 개수만 봐요. 실제 키·토큰은 넣지 않았으므로 "공개한 뒤 주소·QR이 나오는 화면"은 못 봤어요.

### 5.1 첫 화면에서 공유할 주소까지

| 화면 | 읽을 글 | 누를 수 있는 것 | 꼭 해야 하는 것 |

| 처음 | 1,012자 | 버튼 7 | 교재 파일 놓기 |
| 1 교재 넣기 | 683자(더 정하기를 펼치면 839자) | 버튼 6 · 입력 11 | "AI 연결하고 만들기" 또는 "AI 없이 기본 초안만" |
| (AI 연결 대화상자) | 438자 | 버튼 8 · 입력 2 | 키 만들러 나갔다 와서 붙여넣기 |

| 3 공개하기 | 1,087자 | 버튼 6 · 입력 12(고르기 묶음 2) | 토큰 만들러 나갔다 와서 붙여넣기 → "공개하기" |

|---|---|---|

앱 안의 흐름은 짧아요(3단계, 값 5개 자동 채움). 시간이 드는 곳은 **앱 밖 두 번**(AI 키, 올릴 곳 토큰)이에요.

### 5.2 초보자가 멈출 곳

1. **공개하기의 토큰**: 낯선 낱말(토큰, Scope, Expiration, Create)과 영어 화면. 올릴 곳 5개 가운데 고르기, "강사료를 받는 연수면 Cloudflare나 GitHub Pages를 고르세요" 같은 판단도 여기서 해요. 주소가 나오기 직전이라 여기서 멈추면 결과물이 없어요.
2. **AI 키**: "API 키", "Create API key", "만 18세 이상 개인 계정만", 학교 계정이 막힌 경우.
3. **살펴보고 고치기**: 버튼 78개(칸 17개 × 위·아래·이름·숨기기 + 탭 5 + 기기 5 …). 무엇부터 봐야 하는지(빈칸·확인할 곳)가 이 화면 맨 위에 없어요. "마지막 확인"은 3단계에 가서야 나와요.
4. **PPT만 넣었을 때**: 교재 보기에 쪽 그림이 없다는 안내("PDF를 넣으면 그림이 생겨요")가 3단계 공개하기에서 처음 나와요. 1단계로 되돌아가야 해요.
5. **한글·워드 문서를 넣었을 때**: 2단계에서 본문이 없는 사이트를 보게 되는데, 무엇이 빠졌는지 알려 주지 않아요. 1단계의 "교재에서 찾은 것: 실습 n개 · 프롬프트 n개 · 도구 n개 · 링크 n개"는 실습형 기준이라 절차·표·질문을 찾았는지는 안 나와요.
6. **AI로 만든 뒤**: 교재 보기의 쪽 그림이 사라질 수 있어요(§4-5, 코드로 확인: `render/sections.js`의 deck은 설계도의 `src`만 보고, AI 답에는 `src`가 없어요. 앱에서 실제 AI 호출로는 확인 못 함).

### 5.3 줄일 수 있는 단계, 자동으로 정할 수 있는 결정

- 올릴 곳 고르기: 기본 한 곳만 보이고 나머지는 "다른 곳에 올리기"로 접기. 상업·비상업 판단은 1단계의 연수 정보(기관 연수인지)에서 저절로.
- PPT를 넣는 순간 "PDF로도 저장해 함께 넣으면 쪽 그림이 나와요"를 1단계에서 알리기.
- 2단계 맨 위에 "확인할 곳 n개"(빈칸·주의)를 두고, 누르면 그 칸으로.
- 1단계 요약을 유형에 맞게: "절차 5단계 · 표 2개 · 질문 6개를 찾았어요"처럼 교재에서 찾은 것을 그대로.
- AI 연결이 안 됐을 때는 "기본 초안으로 먼저 보기"가 주 버튼. 지금은 주 버튼이 "AI 연결하고 만들기"라 키가 없는 사람이 첫 단계에서 밖으로 나가야 해요.

## 6. 전문성 (연수 사이트로서)

### 6.1 기준으로 삼은 것

- **가네의 아홉 가지 수업 사태**: 주의 끌기 → 목표 알리기 → 이미 아는 것 떠올리기 → 내용 제시 → 학습 안내(예시·발판) → 해 보게 하기 → 되먹임 → 확인 → 파지·전이. 순서를 그대로 따르기보다 주제에 맞게 고르는 계획 도구로 쓰여요. [NIU CITL](https://www.niu.edu/citl/resources/guides/instructional-guide/gagnes-nine-events-of-instruction.shtml), [UF CITT](https://citt.ufl.edu/resources/the-learning-process/designing-the-learning-experience/gagnes-9-events-of-instruction)
- **메릴의 으뜸 원리**: 실제 문제 중심 + 활성화(아는 것 꺼내기) → 시연(보여 주기) → 적용(해 보기, 도움을 점점 줄임) → 통합(자기 일에 옮기기·나누기). [First Principles of Instruction](https://en.wikipedia.org/wiki/First_Principles_of_Instruction)
- **잘 만든 워크숍 사이트(The Carpentries 수업 틀)**: 꼭지마다 맨 위에 질문·목표·걸리는 시간, 맨 아래에 핵심 정리. 연습은 도전 상자에 답을 접어 넣음. 준비(설치) 안내는 따로 한 쪽, 강사용 메모도 따로. [Lesson Organization](https://carpentries.github.io/lesson-example/03-organization), [Lesson Design](https://carpentries.github.io/lesson-example/aio/index.html)
- **행사 사이트 점검표**: 첫 화면에 날짜·장소, 일정·발표자(사진·소속·발표 제목)·등록·문의가 따로 보이고, 휴대폰에서 먼저 읽힘, 쪽마다 h1 하나·그림 대체 글. [Conference Website Checklist](https://bitboxer.de/2016/12/13/conference-websites/), [IEEE Computer Society](https://www.computer.org/conferences/organize-a-conference/organizer-resources/seo-tips), [Ex Ordo](https://www.exordo.com/blog/conference-website-design)

### 6.2 연수 전·중·후

채점 도구(§8)의 기능 체크로 본 값이에요(AI 없이 / AI 경로). 전·중·후 칸에는 "사람 확인" 항목도 들어 있고, 오른쪽 "확실한 18개"는 그것을 뺀 값이에요.

| m1 실습 | 7 / 7 | 5 / 5 | 4 / 4 | 17 / 17 | 받을 수 있는 자료 |

- **중**: 실습형은 단계·프롬프트 복사·완료 체크·교재 보기가 다 있어요. 나머지 유형은 "연수 중에 볼 것"이 없어요(m3는 0/9). 질문·투표·도움 요청은 기본값이 꺼짐이라 다섯 곳 모두 없어요. 300명 설명회도 질문 칸이 없어요.
- **후**: 연수 후 안내·공유·QR 안내문·인쇄는 잘 돼 있어요. **자료실에 받을 수 있는 자료가 하나도 없어요**(파일 이름만 보임, 다섯 곳 공통). 설문은 주소를 넣어야 해요(교재에 설문 링크가 있어도 안 씀).
- 품질 점검(휴대폰 360 폭 가로 넘침 0, axe 위반 0, 그림 대체 글·버튼 이름 빠짐 0, 움직임 줄이기 대응)은 열 곳 모두 통과했어요. 다만 첫 쪽이 외부 요청을 7~30개(글꼴·아이콘 CDN) 보내고 1.0~1.7MB를 받아요. 망이 막힌 학교에서는 글꼴이 안 나올 수 있어요.

### 7.1 모델이 읽고 쓰는 분량 (잰 값)

**앱의 AI 경로**(교재 하나, 한 번 만들기)

- **오히려 못한 점**: ① 문서형·성찰형·과정형·행사형 교재의 본문(AI 없이 23~51%). 그냥 에이전트는 본문을 그대로 옮겨 적으니 내용은 더 충실할 거예요(어림). ② 표를 못 그림(그냥 에이전트는 `<table>`을 씀). ③ 교재에 없는 주소를 덧붙임: 도구 모음의 `padlet.com`·`youtube.com`·`docs.google.com/forms`, 준비 점검의 `accounts.google.com`(채점 도구가 "교재에 없는 주소 4개"로 잡음). 교재의 실제 보드 주소 대신 일반 주소가 실려요. ④ 첫 쪽 외부 요청 7~30개.

## 8. 채점 도구와 랜딩 수치 후보

랜딩에 실을 "그냥 AI 에이전트 vs lecpage" 수치는 다시 잴 수 있어야 해서, 어떤 도구로 만든 사이트든 같은 규칙으로 채점하는 스크립트를 만들었어요. 실제 값은 lecpage를 모르는 새 에이전트 실행으로 채워요. **이 보고서의 §7.2 비교는 어림이에요.**

### 8.1 채점 스크립트

`skills/lecpage/engine/scripts/site-score.mjs` (새 파일, Playwright만 필요. axe-core가 있으면 함께 씀)

```bash
export NODE_PATH=$(npm root -g)
node skills/lecpage/engine/scripts/site-score.mjs <사이트 폴더> --facts facts.json --label 이름 \
  --input-tokens N --output-tokens N --duration-ms N --tool-uses N --human-turns N \
  --price-in <달러/100만 입력 토큰> --price-out <달러/100만 출력 토큰> \
  --edit "문구 한 줄:입력토큰:출력토큰:ms" --edit "순서 바꾸기:입력토큰:출력토큰:ms" \
  --axe <axe.min.js> --out score.json
node skills/lecpage/engine/scripts/site-score.mjs --compare 첫번째.json 두번째.json     # 일관성
```

결과 JSON:

| 자리 | 내용 |
|---|---|
| `run` | `{ inputTokens, outputTokens, totalTokens, durationMs, toolUses, humanTurns, costUsd }` — 실행 기록에서 뽑아 인자로 넣은 값과 단가로 환산한 비용 |
| `edits[]` | 한 곳 고치기마다 `{ name, inputTokens, outputTokens, totalTokens, durationMs, costUsd }` |
| `content.facts` | 핵심 항목 수, 찾은 수, 반영률(%), 첫 화면을 연 상태에서 보이는 비율, 종류별, 빠진 항목 목록 |
| `content.notInSource` | 교재에 없는 주소(수·목록), 교재에 없는 수치(수·목록, 사람 확인) |
| `features` | 연수 기능 23개(전 7·중 9·후 4·운영 3)의 있음/없음, 판정 규칙(`how`), 사람 확인 여부(`human`), `countSure/totalSure` |
| `quality` | 휴대폰 360 폭 가로 넘침 요소 수, axe 위반(심각도별), 내장 검사(대체 글·이름 없는 버튼·이름표 없는 입력·제목 건너뜀·대비 낮음·대비 모름), 움직임 줄이기, 요청 수·외부 요청·받은 용량, 스크립트 오류 |
| `site.bytes` | 폴더 전체 용량과 종류별 |
| `structure` | 제목 목록, 보이는 글자 수 |
| `--compare` | 두 실행의 제목 겹침(%), 기능 차이, 반영률 차이, 품질 차이, 토큰·시간 차이(%) |

판정 규칙이 lecpage에 유리하지 않게 한 것(스스로 점검한 결과):

- 특정 도구의 id·class·파일 이름을 보지 않아요. 화면 글, 표준 요소(`ol`, `table`, `input`, `a[download]`), 브라우저가 잰 값만 봐요.
- 처음 만든 규칙에서 고친 것 세 가지: ① "준비물" 낱말만 찾아서 lecpage의 "시작 전에 준비해요"를 놓침 → 낱말을 넓힘 ② 꺼진 기능의 숨은 버튼("도움 요청")을 있음으로 셈 → **보이는 버튼만** 셈 ③ "질문" 글 근처의 아무 입력 칸이나 질문 받기로 셈 → 입력 칸의 이름표나 가장 가까운 구역 제목이 "질문"일 때만.
- 링크 항목은 화면 글이 아니라 주소(href)에 있어도 찾아요(어느 쪽이든 누르면 가는 곳).
- 탭·접힘 안의 글은 DOM 글로 세고(`rate`), 첫 화면을 연 상태에서 보이는 비율(`rateVisibleOnLoad`)을 따로 내요. lecpage는 실습을 탭에 넣어서 뒤쪽 값이 낮게 나와요(m1: 85% / 62%). 한 장짜리 HTML은 두 값이 같을 거예요. 랜딩에는 앞쪽 값을 쓰되 이 차이를 알고 써야 해요.
- **사람 확인으로 돌린 것**: 프롬프트 복사·질문 받기·투표·도움 요청·강사 화면(글만 있는지 실제로 되는지 화면만으로 못 가림), 교재에 없는 수치(남은 날·개수·쪽 번호처럼 계산한 값이 섞임. lecpage m1에서 21개가 잡혔고 모두 계산값이었어요).
- 한계: 글자 대비는 단색 바탕만 판정해요. 어두운 그라데이션 디자인(m1 glass-lab)은 329곳 중 286곳이 "모름"이에요. axe도 같은 한계가 있어요 → "대비 통과"를 랜딩에 쓰려면 밝은 프리셋으로 재거나 사람 확인을 붙여야 해요.
- lecpage에 불리하게 나오는 항목도 그대로 뒀어요: 받을 수 있는 자료 없음, 교재에 없는 주소 4개, 외부 요청 수, 첫 화면에서 보이는 비율.

### 8.3 랜딩에 쓸 수치 후보

AI를 쓰는 사람이라면 직군과 상관없이 체감하는 것을 앞에 뒀어요. 값은 새 에이전트 실행으로 채워요.

| 순서 | 수치 | 어떻게 재나 | 이번 점검에서 본 것(참고·어림) |
|---|---|---|---|
| 1 | **토큰과 비용**: 입력·출력·합계, 한 번 만드는 비용 | 실행 기록의 입력·출력 토큰 → `--input-tokens --output-tokens --price-in --price-out` → `run.totalTokens`, `run.costUsd`. 두 조건을 같은 모델·같은 단가로 | skill: 읽기 4~6천·쓰기 수백(어림) / 그냥 에이전트: 쓰기 6천~1만(어림) |

| 3 | **오간 횟수**: 사람이 입력한 횟수, 도구 호출 수 | 실행 기록에서 세어 `--human-turns --tool-uses` | 요청문이 되묻지 말라고 해서 두 조건 모두 1이 기준 |
| 4 | **한 곳 고치기**: 문구 한 줄, 순서 하나 바꿀 때 토큰·시간 | `edits.txt`의 두 요청을 같은 세션에서 → `--edit "이름:입력:출력:ms"` → `edits[]`. 고친 뒤 다시 채점해 옛 글이 남은 곳 수와 품질이 그대로인지 확인 | lecpage 패치 0.15초. 다만 첫 화면 장소가 안 바뀜(P1-7) → 이 문제를 고친 뒤에 재야 유리 |
| 5 | **결과물 품질**: 접근성 위반 수, 휴대폰 360 폭 넘침, 용량·요청 수 | `quality.a11y.axe`, `quality.phone360`, `quality.requests`, `site.bytes` | lecpage 열 곳 모두 넘침 0·axe 위반 0. 외부 요청 7~30개는 불리할 수 있음 |
| 6 | **교재 반영률, 지어낸 것** | `content.facts.rate`, `content.notInSource.urls.count`(수치는 사람 확인) | 실습형 85%·98%, 절차형 48%·95% → **절차형은 P0를 고친 뒤에 재야 해요** |
| 7 | **일관성**: 같은 요청 두 번의 차이 | 처음부터 두 번 돌려 `--compare` → 제목 겹침(%), 기능 차이 수, 반영률·품질 차이 | AI 없이 만든 초안은 두 번 모두 같음. AI 경로는 칸 선택이 갈릴 수 있음(§4-2) |
| 보조 | 들어 있는 연수 기능 수 | `features.countSure / totalSure`(사람 확인 5개 제외) | 실습형 17/18 |

주의: 지금 상태로 절차·정책형 교재를 비교하면 lecpage가 반영률에서 질 수 있어요(AI 없이 48%). 랜딩 수치를 재기 전에 P0-1·P0-2를 먼저 고치는 것이 순서예요.
