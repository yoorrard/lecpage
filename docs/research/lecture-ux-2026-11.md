## 2. 화면 연결 구조

```
                       ┌──────────────── 앱: 내 연수 카드 · 공개 완료 '연수 당일' ([강사 화면] 먼저, 키 복사)
                       ▼
  강사 화면(console) ── 들어가기 전: '강사용 화면이에요. 참가자라면 [참가자 화면으로]' + 열쇠 칸만
     │  위 띠: [발표 화면 띄우기]  [더보기 ▾]  밝게·어둡게  [나가기]
     │  맨 위 상자: 발표 화면(지금 보이는 것 · [참여 QR 크게] · [발표 화면 끄기]) · 묻기 방식 · (연수 뒤) [기록·정리로]
     │
     ├─[발표 화면 띄우기]→ 발표 화면(screen) ── 프로젝터(Presentation API) 또는 새 창 + 전체 화면 안내
     │                        ▲ 서버 상태로 이어짐: 투표·결과 공개·타이머·공지·참여 QR 크게
     └─[더보기]→ 참가자 화면 · QR 안내문 · 접속 확인 · 휴대폰에서 열기(키가 든 QR, 누를 때만) · 도움말
                    (새 탭)     (새 탭)    (새 탭)

  참가자 화면(index) ── 공유 창(QR 버튼): QR·주소·연수 코드 + "프로젝터에는 [발표 화면]을 띄워요"(교탁 컴퓨터용)
                     └─ 바닥글: 개인정보 처리 안내 · 접속 확인
  QR·짧은 주소 ─────── 늘 참가자 화면(폴더 주소). 확장자 없는 주소(/poster·/screen·/console)에서도
```

- 모든 보조 화면 머리: 무슨 화면인지(강사 화면은 '강사 화면' 꼬리, 안내문 'QR 안내문', 접속 확인·개인정보는 쪽 이름, 발표 화면은 휴대폰 폭에서만 '프로젝터에 띄우는 발표 화면이에요')와 돌아갈 곳(참가자 화면). 강사 화면에서 연 쪽은 새 탭이라 탭을 닫으면 강사 화면으로 돌아옴(같은 탭에서 강사 화면을 다시 열면 키를 또 물으므로 '강사 화면으로' 링크는 두지 않음).
- 발표 화면의 프로젝터 폭 위 띠에는 강사 화면으로 가는 링크를 두지 않음(도구 서랍 안 [강사 화면 열기]만).

## 3. 발표 화면 열기·조종

- **[발표 화면 띄우기]** 한 단추가 알아서:
  1. 크롬·엣지에 두 번째 화면(프로젝터·외부 모니터, 확장 모드)이 있으면 `PresentationRequest('screen.html')` — 브라우저가 화면 고르는 창을 한 번 띄우고, 고른 화면에 **바로 전체 화면**으로(1-UA 모드, Chrome 66부터 Windows·ChromeOS·Linux). 받는 쪽은 누를 사람이 없으니 위 버튼을 모두 숨김. 크롬캐스트·캐스트 되는 TV도 같은 창에 나옴. 강사 화면에 "프로젝터에 발표 화면을 띄웠어요" + [발표 화면 끄기]. [더보기]에 "발표 화면 새 창"이 따로 생김(고르는 창 대신 창으로 열 때).
  2. 그 밖(파이어폭스·사파리·웨일, 화면이 하나 = 복제 모드, 고를 화면이 없음): `window.open('', 'lp-screen', 'popup,1280×720')` — **탭이 아니라 창**이라 끌기 쉬움. 발표 화면이 이 이름을 보고 "프로젝터에 띄워요 — 끌어다 놓고 [전체 화면]" 안내를 띄우고 [전체 화면]에 초점(Enter 한 번). 복제 모드면 "바로 누르면 돼요". 이미 연 창이 있으면 다시 불러오지 않고 앞으로만(강사 화면을 새로 고쳐도 이름으로 찾음). 이를 위해 `_headers`에서 발표 화면도 강사 화면과 같은 COOP(`same-origin`).
- **조종**: 모두 서버 상태라 노트북·휴대폰 어느 강사 화면에서 눌러도 같은 발표 화면에 바로. 새로 넣은 것은 `state.ui.qrBig`(참여 QR 크게) 하나 — 다섯 백엔드가 모두 `ui`를 키 이름 그대로 받아 서버 코드 변경 없음. 발표 화면에서 큰 QR을 직접 닫으면(강사 화면이 연 창이라 키가 있을 때) 스위치도 꺼짐.
- **휴대폰을 리모컨으로**: 따로 리모컨 화면을 만들지 않고 **강사 화면 자체**가 휴대폰에서 돌아감(이미 한 단 배치). 막혔던 것은 휴대폰에 23자 키를 치는 일 하나 → [휴대폰에서 열기] QR(`console.html#key=…`)로 해결. 휴대폰 폭에서는 [발표 화면 띄우기]를 숨김(이 기기에 띄울 일이 없음. 캐스트할 화면이 있을 때만 보임).

## 4. 참가자가 강사용 화면에 섞이지 않게

| 점검 | 이미 된 것 | 이번에 더한 것 |
|---|---|---|
| 참가자 화면·안내문·발표 화면에서 강사 화면으로 가는 눈에 띄는 링크 | 참가자 화면에 없음(바닥글은 개인정보·접속 확인) | **안내문의 '강사 카드'(강사 화면 QR·주소, 기본 켜짐)를 뺌** — 참가자 손에 가는 종이·화면. 공유 창에 '발표 화면' 링크 하나(보기 전용, 교탁 컴퓨터용) |
| QR·짧은 주소가 늘 참가자 화면 | 짧은 주소는 글자로만, QR은 원래 주소 | **확장자 없는 주소에서 QR이 그 쪽 자신을 가리키던 문제**(전: `/poster`의 QR → `/poster`, `/screen` → `/screen`, 강사 화면 참여 QR → `/console`; Cloudflare Pages는 `/poster.html`을 `/poster`로 넘김)를 고침: 늘 폴더 주소. `meta.siteUrl`이 있으면 그 주소(전과 같음) |
| 참가자가 강사 화면 주소로 | 키 없으면 아무것도 못 함(서버 401·403·429) | 첫 화면(휴대폰에서도 스크롤 없이)에 "강사용 화면이에요. 참가자라면 [참가자 화면으로]". 다른 화면 버튼·도움말·연결 상태는 **들어간 뒤에만** |
| 참가자가 발표 화면 주소로 | 키 없으면 바꿀 수 없음(도구는 그 기기 안) | 휴대폰 폭(700px 미만)에서만 맨 위 "프로젝터에 띄우는 발표 화면이에요. [참가자 화면으로]" — 프로젝터에는 안 보임 |
| 강사 키·강사용 QR이 투영되지 않게 | 키는 화면·주소·DOM에 없음 | 휴대폰 연결 QR은 **강사 화면에만**, [더보기] → [휴대폰에서 열기] → **[QR 보이기]를 한 번 더** 눌러야 보이고(경고: "프로젝터나 화면 공유에 이 창이 비치지 않을 때"), **60초 뒤·창을 떠나면·닫으면 다시 가림**. 휴대폰은 `#key=`를 읽자마자 주소에서 지우고 이 탭에만 둠. DOM에 키 글자 없음(QR 그림에만) |
| 검색 제외 | 모든 보조 화면 `noindex`, `X-Robots-Tag`, 공개 범위가 '누구나'가 아니면 robots.txt Disallow | 확인만 |

## 6. 넣지 않은 것과 이유

- **창 관리 API(`getScreenDetails`)로 창 자리 잡기**: 권한 창이 하나 더 뜸. 같은 경우(크롬·엣지 + 두 번째 화면)를 Presentation API가 고르는 창 한 번으로 더 잘 함.
- **휴대폰용 '조종만 되는' 따로 키**(지우기·명단은 못 하는): 다섯 백엔드와 바로 공개 방에 새 권한을 넣어야 함. 키가 든 QR을 누를 때만·60초·창을 떠나면 가림으로 단순하게. 남는 위험: 강사가 복제 모드로 투영하면서 [QR 보이기]까지 누르면 60초 동안 비침 → 경고 문구와 두 번 누르기로 막음.
- **복제 모드 자동 감지·투영 중 자동 숨김**: 브라우저가 복제 모드를 알려 주지 않음.
- **발표 화면 한 글자 단축키·리모컨 쪽 넘기기**: WCAG 2.1.4(앞 작업과 같은 결정). 발표 화면 무대는 강사 화면이 바꿈.
- **인쇄용 강사 카드**: 뺌. 하던 일(휴대폰으로 강사 화면 열기·주소 모음)은 [휴대폰에서 열기]와 앱 '내 연수' 카드가 맡음. `handouts`도 `QR-안내문.pdf`만.
- **강사 허브 쪽을 따로 만들기·참가자 화면에 '강사용' 링크**: 화면만 늘어남. 강사 화면이 곧 허브.
- **보조 화면에 '강사 화면으로' 링크**: 새 탭에서 강사 화면을 다시 열면 키를 또 물음. 탭을 닫으면 돌아옴.
