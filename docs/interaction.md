# lecpage 동작 기준(누름·기다림·실패·초점·움직임)

앱 화면과 lecpage가 만드는 연수 사이트에 같이 씁니다. 글은 [writing.md](writing.md), 화면 배치는 `skills/lecpage/references/design-quality.md`.
**[검사]** 표시는 `node app/scripts/interaction-check.mjs`가 확인합니다(앱 첫 화면·1~3단계·도움말·설정·갤러리, 강의 페이지 예시 2종, 휴대폰 흉내 포함). 나머지는 화면을 고칠 때 눈으로 봅니다.

```bash
npm --prefix app run build && npm run examples
node app/scripts/interaction-check.mjs          # 표(통과·실패·살핌). --json, --only=app|site, --base=이미 띄운 주소
```

## 1. 누름 반응
- 누른 뒤 **100ms 안에** 화면이 달라진다(눌린 모양, 선택 표시, 다음 화면 시작). **[검사]** CPU 4배 느리게 해도.
- 0.3초 넘게 걸릴 일은 버튼 안에 "~하는 중…"을 띄우고 그동안 다시 누를 수 없게 한다. 버튼 폭이 바뀌어 옆 버튼이 밀리지 않게.
- **두 번 눌러도 한 번만** 일어난다. 누르는 순간 막는다(진행 중 표시를 기다리지 않음). **[검사]** 연수 만들기 버튼을 빠르게 두 번.
- 입력을 다 하기 전에 제출 버튼을 미리 끄지 않는다. 누르면 빠진 칸을 알려 준다.

## 2. 기다림
| 걸리는 시간 | 보여 줄 것 |
|---|---|
| 0.1초 안 | 아무것도(결과만) |
| 0.1~1초 | 0.3초 지나도 안 끝났을 때만 표시. 한 번 띄우면 0.5초는 둔다(깜박임 방지) |
| 1~10초 | 무엇을 하는지 한 줄: "교재를 읽는 중…" |
| 10초 넘음 | 진행 정도(“슬라이드 그림 12/40”, 진행 막대), 대략 남은 시간, **멈추기** 버튼, 다른 일을 해도 되는지 |

- 뼈대(skeleton)는 다 뜬 모양과 **같은 크기**로. 내용이 뜨면서 아래가 밀리면 안 된다(3절). **[검사]** 화면을 옮길 때 CLS 0.1 아래.
- 기다림 안내와 끝난 결과는 화면 읽기 프로그램도 알게 `aria-live="polite"`(알림은 `role="status"`). **[검사]** 느린 망에서 도움말 처음 열기.
- 화면 하나를 통째로 늦게 불러올 때는 바닥글이 위로 올라왔다 내려가지 않게 본문 자리 높이를 잡아 둔다.

## 3. 실패와 복구
- **되돌리기가 먼저, 확인 창은 나중.** 되돌릴 수 있는 일은 바로 하고 알림에 [되돌리기]를 둔다.
- 실패하면 **입력한 것을 그대로 둔다**(다시 적게 하지 않음). 오류는 그 칸 옆에, 제출할 때는 첫 오류 칸으로 초점.
- 실패 알림에는 [다시 하기] 또는 다음 할 일. 네트워크·외부 서비스 실패는 한 번은 저절로 다시 해 본다.
- 먼저 화면에 반영한 것(완료 체크·반응)이 서버에서 실패하면 되돌리고 알린다. 조용히 사라지게 하지 않는다.
- 원래 오류 문구(영어 등)는 접어 두고 펼쳐 볼 수 있게.

## 4. 확인 창
| 쓰는 때 | 쓰지 않는 때 |
|---|---|
| 되돌릴 수 없고 잃는 것이 큰 일: 지우기, 덮어쓰기(처음부터 다시 만들기), 공개 범위를 넓히기, 돈이 드는 일 | 되돌릴 수 있는 일(→ 되돌리기), 자주 하는 일, 정보만 알리는 일(→ 알림·글) |

- 제목은 질문("○○를 지울까요?"), 본문은 바뀌는 것과 남는 것, 버튼은 [동작 이름] [닫기].
- 열면 **안전한 쪽**(닫기)이나 제목에 초점. 위험한 버튼에 초점을 두면 Enter 두 번으로 지워진다.
- 열면 초점이 창 안으로, Tab은 창 안에서만 돌고, **Esc로 닫히며, 닫으면 연 버튼으로 초점이 돌아간다.** **[검사]**
- 들어오자마자 화면을 가로막는 창, 뒤로 가기를 가로채는 창은 띄우지 않는다(writing.md 7절).

## 5. 초점
- 키보드로 옮긴 초점은 **늘 보인다**: 2px 이상 바깥선, 배경과 대비 3:1 이상. `outline:none`만 두지 않는다. **[검사]**
- 초점 받은 것이 **가려지지 않는다**: 위에 붙은 머리(sticky)·아래 떠 있는 버튼 줄(독)만큼 `scroll-padding-top/bottom`을 둔다. **[검사]**
- **보이지 않는 것에는 초점이 가지 않는다**(접힌 메뉴·0 크기·화면 밖은 `hidden`·`inert`). **[검사]**
- 화면·단계를 옮기면 새 화면 제목으로 초점(**[검사]** 단계 이동). 항목을 지우면 다음 항목이나 목록 제목으로.

## 6. 키보드
- 모든 일은 키보드만으로 된다. Tab 순서는 읽는 순서와 같다. 첫 Tab에 "본문 바로 가기". **[검사]** 키보드만으로 1→2단계(지금 Tab 28번).
- **Enter**: 버튼·링크 실행, 입력칸 하나짜리 양식 제출. 여러 줄 칸은 Enter가 줄바꿈이고 Ctrl/⌘+Enter가 보내기.
- **Space**: 체크·선택·버튼. **Esc**: 창·시트·메뉴 닫기(입력 중이면 입력 취소가 먼저). **화살표**: 탭·라디오·메뉴 안에서 옮기기.
- 단축키는 화면에 적고, 글자 하나짜리 단축키는 입력칸 안에서 동작하지 않게.

## 7. 누르는 곳 크기
- 모든 누르는 곳은 **24×24px 이상**, 작으면 둘레에 다른 누르는 곳이 없어야 한다(WCAG 2.5.8). **[검사]**
- 터치 화면(`pointer: coarse`)에서는 **44×44px**. 붙은 버튼 사이는 8px. 보이는 모양이 작으면 누르는 영역만 넓힌다. **[검사]**
- 문장 속 링크는 예외. 체크·라디오는 이름표까지 한 덩어리로 누르게.

## 8. 붙여넣기·끌어다 놓기
- 붙여넣기를 막지 않는다. 붙여 넣은 값의 앞뒤 공백은 지운다. 키·주소 칸은 붙여 넣자마자 형식을 확인하고 결과를 칸 옆에.
- 끌어다 놓기: 놓을 곳을 강조하고(놓으면 무엇이 되는지 글로), 같은 일을 [고르기] 버튼과 키보드로도 할 수 있게. 받을 수 없는 파일은 이유와 함께 알린다.

## 9. 자동 저장
- 저장은 조용히: 머리의 "자동 저장" 글자처럼 늘 같은 자리에. 실패할 때만 크게 알리고 [다시 하기].
- 탭을 닫거나 다른 화면으로 갈 때 아직 안 쓴 것이 있으면 바로 쓰고(`pagehide`), 쓸 수 없으면 떠나기 전에 묻는다.
- 이 브라우저에만 저장된다는 사실과 다른 컴퓨터로 옮기는 방법(파일로 저장)을 저장 표시 가까이에.

## 10. 새 창 갔다 돌아올 때
- 다른 서비스(AI 키 만들기, Vercel, Apps Script, Supabase)는 새 창으로 열고 버튼 이름에 그 곳을 쓴다.
- 돌아오면(`visibilitychange`) 하던 단계 그대로, 상태를 다시 확인한다(연결 시험, 붙여 넣을 키가 클립보드에 있는지는 묻고 확인). 다음에 누를 곳으로 초점이나 강조.
- 오래 비운 뒤 돌아오면 바뀐 것을 한 줄로 알린다(예: "참여 기능 연결이 끊겼어요. [다시 연결]").

## 11. 움직임
- 움직임은 **원인과 결과를 보여 줄 때만**(어디서 나와 어디로 갔는지, 무엇이 바뀌었는지). 장식 움직임은 연수 사이트 디자인 프리셋이 정한 자리에만.
- 길이: 누름 반응 70~110ms · 작은 펼침·알림 150~250ms · 큰 펼침·화면 전환 300~400ms · 배경 어둡게 700ms 이하. 0.5초 넘는 반응 금지.
- 가감속: 들어올 때 감속(ease-out), 나갈 때 가속(ease-in), 화면 안 이동은 ease-in-out. `transform`·`opacity`만 움직이고 `transition: all`은 쓰지 않는다. 누르면 바로 끊긴다.
- **움직임 줄이기**(`prefers-reduced-motion: reduce`): 움직임 0, 나타남·사라짐은 바로. 진행 막대처럼 기능인 것은 남긴다. **[검사]** 실행 중 애니메이션 0, 0.7초 사이 화면 그대로.
- 5초 넘게 저절로 움직이는 것(흐르는 띠, 배경 효과)은 멈춤 버튼을 둔다.

## 12. 휴대폰
- 마우스를 올려야만 보이는 정보·버튼 금지(터치에는 hover가 없다).
- 입력칸 글자 16px 이상(iOS가 확대하지 않게). 확대를 막지 않는다. **[검사]**
- 화면 키보드가 올라와도 입력칸과 보내기 버튼이 가려지지 않게. 아래 고정 줄은 안전 영역(`env(safe-area-inset-bottom)`)만큼 띄운다.
- 길게 누르기·밀기만으로 하는 일은 없게(같은 일을 버튼으로도).

## 13. 강의 페이지(참가자 화면) 반응
참가자는 실습하며 곁눈으로 봅니다. 강사는 앞에서 여러 사람을 동시에 봅니다.
- 완료 체크·반응·투표는 **누르는 즉시** 화면에 반영하고 서버는 뒤에서. 실패하면 되돌리지 말고 "아직 못 보냈어요. 다시 보낼게요."로 저절로 다시 보낸다(인터넷이 끊겨도 체크는 남김).
- 도움 요청·질문은 보낸 뒤 상태를 보인다(보냄 → 강사가 봄). 같은 요청을 겹쳐 보내지 않게.
- 프롬프트 복사는 버튼 글자가 1.5초 "복사했어요"로 바뀌고 돌아온다(알림 창을 띄우지 않음).
- 아래 떠 있는 참여 버튼 줄(독)이 초점 받은 칸·입력칸을 가리지 않게(`scroll-padding-bottom`).
- 강사 화면 목록은 새 글이 들어와도 보던 자리가 밀리지 않게, 위에 "새 질문 3개" 버튼으로 모은다. 발표 화면도 움직임 줄이기를 따른다.
