# 점검 목록

## 자동(`make`·`patch --qa`·`qa dist`)
- 휴대폰(390px)·PC(1280px) × 밝게·어둡게 4화면: 스크립트 오류 0, 가로 넘침 없음, 그림 대체 텍스트, 이름 없는 버튼, h1 하나
- 깨진 자료: 페이지가 가리키는 그림·파일(`assets/slides`·`assets/media` 등)이 실제로 있는지
- 디자인 검사(`scripts/design-lint.mjs`)·문구 검사(`scripts/copy-lint.mjs`): 파일이 있으면 함께 돌리고, 없으면 "검사 없음(건너뜀)"으로 알림
- Playwright가 없으면 화면 검사만 건너뛰고 깨진 자료는 그대로 확인한다(`doctor`로 설치 방법)
- 결과: 요약 한두 줄, 문제는 화면마다 한 줄. 자세히는 `qa/report.json`, 스크린샷은 `qa/*.png`

**스크린샷은 직접 연다.** 숫자가 통과여도 빈 칸, 너무 긴 문구, 겹친 글자, 그라데이션 위 흐린 글씨는 눈으로만 보인다. 고칠 곳은 `patch`로 고치고 `--qa`로 다시 본다.

## 사람 점검(빌드할 때마다)
- [ ] 첫 화면의 연수명·일시·장소·강사가 교재·강사 답과 같은가
- [ ] 실습 프롬프트가 교재 원문과 같은가(복사 버튼으로 붙여 넣어 확인)
- [ ] 도구 링크가 모두 열리는가(`check.html` 접속 진단)
- [ ] 교재 뷰어 쪽 번호와 도구 카드의 쪽 번호가 맞는가
- [ ] 휴대폰에서 너무 긴 카드·버튼이 없는가
- [ ] '움직임 멈춤' 버튼과 동작 줄이기 설정에서 화면이 멀쩡한가
- [ ] 실시간: 두 기기로 질문·막혔어요·완료 체크를 보내 강사 화면에 보이는가, 공지·타이머가 참가자 화면에 뜨는가
- [ ] 개인정보: 수집 항목과 동의 문구가 맞는가, `privacy.html` 내용 확인
- [ ] 관리자 키·암호가 설계도·저장소·사이트 파일 어디에도 없는가
- [ ] 올릴 폴더(`dist/`)에 `DESIGN.md`·`운영안내.md`·설계도가 없는가(`dist-강사용/`에만)

## 디자인 고를 때(`options`)
- [ ] 비교 그림(`work/options/contact-sheet.png`)을 강사에게 보여 주고 고르게 했는가. 세 안의 차이를 한 줄씩 말해 준다
- [ ] 기관 색(`design.accent`)을 넣었다면 버튼 글씨가 잘 읽히는가

- [ ] 프로젝터에 `screen.html`을 띄워 QR이 뒷자리에서도 찍히는지
- [ ] Supabase 무료 프로젝트라면 깨어 있는지(강사 화면 로그인으로 확인)
- [ ] 휴대폰 하나로 참가자 흐름 끝까지(입장 → 실습 → 질문 → 설문)
