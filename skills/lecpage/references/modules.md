# 사이트 유형과 기능 모듈

## 1. 구성 정하기: 흐름과 신호
유형 하나를 골라 정해진 칸만 쓰지 않는다. 컨셉 → **흐름** 하나 → 교재의 **신호마다 칸을 더한다**. 엔진 `decide/structure.js`가 정하고(`structure` 명령이 큰 줄기까지 보여 줌), AI 프롬프트도 같은 표를 쓴다.

| 흐름(id) · 유형 | 언제 |
|---|---|
| 따라 하기 follow · lab | 번호 단계 + 도구·프롬프트가 있는 실습 |
| 절차·기준 procedure · story | 번호 단계만 있는 절차·규정 |
| 사례·토론 discussion · story | 사례·함께 나눌 질문·성찰 질문 |
| 과정 course · course | 차시 둘 이상, 직무연수 |
| 행사 event · live | 참석 100명 이상이거나 발표자 여럿 |
| 강의 talk · story | 메시지·설명 중심 발표 자료 |
| 교재 순서대로 source · story | 위 신호가 없는 한글·워드 문서 |

강사가 고른 형식이 먼저다. 컨셉은 신호가 약할 때(강의·교재 순서대로)만, 교재에 그 재료가 있을 때 흐름을 바꾼다. 문서 교재의 본문은 교재의 절 순서를 따른다.

| 교재에서 보이는 신호 | 칸 | 자리·권하는 기능 |
|---|---|---|
| 번호 단계 + 도구 주소·프롬프트 | stations(prompts·tools·readiness) | 실습 앞쪽. 진행 현황·도움 요청 |
| 번호 단계만, 제목이 절차·대응·방법 | procedure | 수치 → 절차 → 기준표 |
| 머리글 줄이 있는 표(기준·역할·적용 일정) | table | 그 내용 바로 뒤 |
| "n분 이내", "%", "n회에서 n회로" | glance | 첫 화면 바로 아래 |
| "사례 1·2·3", 따옴표 인용 | cases | 본문 맨 앞 |
| 물음표 목록 3개 이상, 토론·나눔 제목 | discuss(+ rules) | 사례 뒤. 나눔 보드 |
| "~적어 보세요", 성찰·일지 제목 | reflection | 마무리 앞 |
| "n차시 + 날짜" | sessions | 차시. 출석 |
| 이수 기준·출석 %·과제·제출 기한 | meta.admin, followup | 연수 후. 출석 |
| 시각 + 이름, 발표자 소개 | schedule + speakers | 강사 칸 대신 발표자 칸 |
| 참석 100명 이상·설명회 | glance·schedule·speakers | 실습·준비 점검 빼기. 질문 받기·투표 |
| 서식·양식·글상자 예시문 | text의 `> [!예시]` | 뒤쪽 |
| 노트의 "막히면·안 되면·주의" | stations[].note | 그 실습 안 |
| 어디에도 맞지 않는 문단·표 | text | 교재 순서 그 자리(버리지 않음) |

**가드레일**(검증이 알리기만 하고 옮기지 않음): 첫 화면 → 무엇을 얻나(goals) → 준비 → 본문 → 자료·연수 후 → 강사 → 설문 → 마무리. 설문은 마무리 앞(마무리 문장에서 사람들이 멈춤). goals는 메뉴에 넣지 않고 첫 화면 바로 아래. 실시간 기능은 권하기만 하고 강사가 고를 때만 켠다. 그래도 칸에 못 실은 교재 글은 `structure.leftovers`("싣지 못한 것 n개") → `structure --add-leftovers`.

### 2.1 참가자·강사 화면에 덧붙은 것(2026-11)
- 휴대폰(600px 아래): 메뉴 대신 **목차** 버튼(아래에서 올라오는 시트), 위쪽 **'지금' 줄**(열린 투표·공지·타이머·강사가 보는 실습/쪽과 버튼 하나), 도움 요청은 자리를 묻는 작은 시트로(자리는 기기에 기억). 데스크톱 메뉴는 6개까지 보이고 나머지는 '더보기'.
- 강사 화면(`console.html`): 켜진 기능의 패널만, 맨 위 '지금' 띠(참여자·도움 요청·모르겠어요 %·열린 투표), **기록 내려받기** 한 메뉴(참여자·출석·**이수자 명단**·실습 진행·질문·보드 글·도움 요청·투표 응답·설문), 투표 **결과 공개/숨기기**(참가자는 공개 뒤에만 결과를 봄), **신호 초기화**, 워드클라우드 **단어 숨기기**.
- 이수자 명단 CSV(`completion`): 별명·이름·소속·입실·퇴실·머문 시간(분, 연수 시간 안만)·실습 완료(n / 전체)·설문 제출·이수(O·X·확인 필요). 기준은 `meta.admin.completionRate`%와 설문 문항이 있으면 설문 제출. 입실·퇴실 기록이 없으면 '확인 필요'. 개인 번호는 담지 않음.
- 발표 화면(`screen.html`)의 **도구**: 이름 뽑기(모두 뽑힐 때까지 중복 없음, 참가자 별명 불러오기), 모둠 무작위 나누기, 타이머 여러 개. 실시간 연결 없이도 동작.
- `poster.html`: A4 한 장 QR 안내문(제목·일시·장소·큰 QR·주소·연수 코드·Wi-Fi 적는 줄) + 따로 인쇄되는 '강사만' 카드(강사 화면·발표 화면·접속 확인 주소).
- 새 상태 값은 서버가 모르는 키를 버리므로 `state.ui`에 둡니다: `ui.reveal`('투표id|…'), `ui.signalReset`(ms), `ui.hiddenWords`('낱말|…'), `ui.timers`(JSON 문자열). 워드클라우드는 NFC·소문자·조사 하나(은는이가을를의에도요) 떼기·합치기·금지어 빼기를 거칩니다.

## 3. 연수 전·중·후: 무엇이 먼저 보이나
사이트 하나가 세 시기를 모두 맡는다. 첫 화면 바로 아래(휴대폰 첫 스크롤)에 오는 것이 시기마다 다르다.

| 시기 | 참가자가 찾는 것 | 첫 화면·바로 아래 |
|---|---|---|
| 전(공문·QR을 받고) | 언제·어디서·어떻게 들어가나, 무엇을 얻나, 무엇을 준비하나 | hero(일시·장소·입장 버튼) → goals(목표·대상·이수 기준) → readiness |
| 중(연수 당일) | 지금 할 일, 실습 단계, 프롬프트, 도움 | '지금' 줄(실시간), schedule의 지금 순서, stations, 도움 요청 |
| 후(연수가 끝난 뒤) | 다시 보기, 자료, 설문, 이수 처리, 문의 | '끝난 연수' 줄 → followup(첫 화면 아래로 올라옴) → materials·survey |

- 시기는 `meta.date`·`meta.start`·`meta.end`와 차시 날짜로 계산한다(`lp-data.phase`). 주소 끝에 `?phase=after`를 붙이면 끝난 뒤 보기를 미리 볼 수 있다.
- 차시(sessions)는 상태를 적지 않으면 날짜로 '마침·오늘·다음'이 붙는다. 차시마다 `#<섹션id>-<번호>` 주소가 있어 공지에 바로 걸 수 있다.
- 온라인·혼합(`meta.mode`)이면 `meta.joinUrl`이 첫 화면 첫 버튼("Zoom 입장" 등)이 되고, 장소에 "온라인 (Zoom)"이 붙는다. 끝난 뒤에는 숨는다.
- 교육청 승인 직무연수(`meta.admin.kind: official`)면 이수 기준("3시간 · 출석 80% 이상 · 설문 제출")이 연수 목표 칸에(없으면 첫 화면에), 출석·설문 칸에 "이수가 확인돼요" 안내가 붙는다.

## 4. 넣지 않은 것(검토 후 뺌)
| 후보 | 결정 |
|---|---|
| 글자 크기 조절 버튼 | 브라우저 확대(Ctrl +, 손가락 확대)로 충분. 확대를 막지 않고 200%에서도 줄바꿈되게 유지 |
| 인쇄용 실습지 버튼 | 브라우저 인쇄로 모든 실습이 펼쳐져 인쇄됨(인쇄 CSS). 버튼은 늘리지 않음 |
| 차시별 별도 페이지 | 한 페이지 + 차시 앵커 + 날짜 자동 표시로 충분. 페이지를 나누면 QR·메뉴·실시간 연결이 갈라짐 |
| 지난 일정 접기('오늘' 보기) | 일정은 6~8줄이라 지난 순서를 흐리게 하는 것으로 충분 |
| 시간대 표시 | 국내 연수는 한국 시간 하나. 해외 참가자가 있으면 hero.meta에 직접 적음 |
| 오늘 만들 것 미리보기 칸 | goals 문장과 실습 outcome, 보드·갤러리로 충분. 새 칸을 늘리지 않음 |
| Wi-Fi 칸, 지도 칸 | Wi-Fi는 QR 안내문(poster)에 적는 줄이 있음. 지도는 hero.meta 항목에 `url`을 걸면 됨 |
| 사이트 저작권 표시 칸 | 교재·자료 칸의 `notice`와 보드 이용 조건으로 충분 |
| 채팅 | 질문·나눔 보드로 충분. 강사가 살필 곳만 늘어남 |
| 사이트 안 사전 설문 | 설문 답은 참가자마다 하나만 저장돼 사전·사후를 나눌 수 없음. 사전 설문은 구글 설문 같은 외부 주소를 readiness 항목에 링크 |
